# 健康数据颜色编码——设计逻辑与边界

## 内容目的与品牌语言
原作是健康监测界面的双屏与组件放大版：左准备度先给单一87分与四项构成；中间睡眠依次从总时长→分期→三个指标→夜间趋势；右侧将活动三环与状态色单独讲解。黑背景、纯黑设备屏、略亮暗卡形成层次，不靠大片灰来替代暗黑模式。

## 色彩与层级
蓝色承担准备度最佳状态与趋势线；紫色分级表示睡眠阶段，青色与橙色标出其他分期。红/黄用于指标状态，而活动三环粉红/荧绿/青色是类别编码，不应把绿色自动解释为正常、红色自动解释为危险。文字标签补充色彩含义，但本例未做色觉障碍或无障碍合规认证。原作绿环有内容语义，所以保留，而非默认浅绿审美。

## 实现方法与积木
原 HTML/CSS/SVG 的布局、文本、弧线和折线移植为固定尺寸原生 Canvas。真实调用 design.material-surfaces.v1 三次：两设备底层和右侧大浮卡。其来源模块 SHA 记录在验证清单；这是材质/表面复用，不是把整张健康UI冒称资产。86px高状态卡低于该组件100px契约，用案例原生代码忠实绘制，不缩放硬套。

radial-scale.v1 的刻度/表盘/限定弧度不适配完整进度圆环；authored-paths.v1 强制附图例与图注布局，不能保持源微型HRV示意区；semantic-data 不是睡眠柱列。三者不强套。新增通用资产0。无 imagegen、外部照片、3D；材质组件内部 drawImage 仅过程生成的阴影遮罩，不是截图。

## 自检与数据边界
所有87分、睡眠时长、HRV折线、环数据都是原作UI示意，非实测、非医疗判断。原作活动弧长473/(2π×92)约81.8%，不等于512/600约85.3%；锻炼弧长330/(2π×68)约77.2%，不等于26/30约86.7%；站立约57.9%接近7/12约58.3%。忠实保留源弧线但明确记录不一致，未把它升级为定量/临床可靠控件。准备度87分弧约86.9%。详上述编码差异为本例限制，本地检验回执不随源码发布。

## 验证范围与残差
固定1200×750，完整作品含源设备下方出框构图。只做静态Native与独立视觉复核，不是可交互健康app。源JPEG、柔影范围、局部字距有微小残差；不宣称浏览器、响应式、视频、医疗和无障碍测试通过。

案例专用 soft-mask.mjs 补大/小浮卡漫影，未更改通用积木。已修复两场景同进程字体别名冲突，改为 Ocean*/Health* 独立注册；交付需同进程和独立官方引擎输出字节一致。
