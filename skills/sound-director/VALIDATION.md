# 声音导演验证：结构、执行、效果分开

本文件是仓库验证计划，不保存私有作品结果。先读 [工作流](../motion-film-director/references/sound-direction.md)，真实媒体与记录放授权项目目录。

## 能力对齐

| 两位现有导演的职责 | 声音导演对应工作 | 不能冒称 |
|---|---|---|
| brief、参考研究、适用边界 | 辨明人声/配乐/整轨，真实听参考，比较职责与来源 | 看频谱就是听过 |
| 方向与素材选择、实现指导 | 声音脚本、配乐/SFX选择、台本与表演指令、可执行混音 | TTS/作曲/自动ducking已内置 |
| 版本交接、复验 | 同画面A/B、源→输出时间映射、锁版本、受影响范围回归 | 交接存在就是成片通过 |
| 独立审核和反馈回流 | 不先告诉审查者“应当更好”，提供目标与反证、实际媒体，分开审查与用户接受 | 未听审时通过艺术门 |
| 私有Case、方法/资产沉淀 | 沿既有知识库和资产生命周期，以来源、适用、失败与权利区分复用/公开 | 一次局部认可就是通用配方 |

## 真实任务验证顺序

1. 选一个已授权私有影片和当前声音问题，不选只有蜂鸣/静帧的技术夹具作为作品。记录导演入口、任务、保留项、版本/hash、权限、听审可用性。允许用真实旧失败片做诊断，不将其改称成功作品。
2. 完整走声音工作流：读相关原文与实际核心合同，形成声音脚本；保留具体采用/弃用决策。人声不适用写原因，不添加无关配音。如果人声分支没做，明确未验，另以获授权人声任务验证。
3. 在仓库外执行一次真实核心时间线解析/混音与最终封装检查，或绑定当前同hash已执行产物；仅重用旧报告不能证明新导演做过制作。新增版本时保留基线与精确变更，不为演示改好坏未知的声音。编解码、源身份、源→时间线映射失败应停止对应产物晋级。
4. 完成一次跨导演交接：需接续制作或可迁移交付时，按 [可重建交接](../motion-film-director/references/rebuild-handoff.md) 检查完整命令、根绑定及输入恢复，并在新授权项目根执行；同机原路径可跑不算迁移通过。Motion提供画面事件/读时，声音返回cue/人声/音乐决策与未验项；UI只在字幕、界面状态或视觉信息冲突时参加，确认语义和阅读空间。记录接收方采用/拒绝理由，不用伪造来回消息充次数。
5. 独立审查真实输出和反例：技术审查可自动化；听审者必须实际访问声音并说明范围、方式和观察；影片常速声画另验。先不给听审者“新版应该更好”的结论。没有听审能力，最多得出技术执行/流程候选结果，并保持 NOT_LISTENED，不能宣布导演质量验证完成。
6. 把结论写入同一私有Case，技术、听审、声画、用户接受和公开权分列。由实际反馈选择保留/撤回；仅有技术改善不推导听感改善。公开仅提炼经审定、去素材化且带反例的方法，不自动扩音效库或portfolio。

停止条件是完成对应任务和证据门，或明确阻断/待用户授权；不是凑足迭代次数。真实听审不可用就交代缺口，不以结构测试替代。需要声线样本、外部上传/服务或发布时按当前授权另处理。

## 必测反例（记录真实结果，不造听审）

- 只有候选网页、许可与技术测量：参考/输出仍 `NOT_LISTENED`，可以交技术草案，不能交“研究完成/更好听”的结论。
- 只有参考听审：输出质量与常速声画仍未验；只有输出听审：不能倒补参考分析完成。
- 只有模型音频结果或人耳局部记录：不扩大为全片连续声画通过。新混音/重编码后不复用旧 hash 的通过记录。
- 实际展示不能播放或尚无用户反馈：保留交付问题/待反馈，不把生成 listen 页面或“已发送”当用户听过。
- 参考听审和许可齐备但只改一个 cue：复核受影响关系及最终上下文，不强制额外扩库、全新配乐或固定数量参考。

以下离线测试只保护文字路由、已有候选/通过门和技术合同，无法认证真人听过；真实任务仍须逐项执行以上反例与原始证据核对。

## 可复跑的离线检查

从仓库根运行：

```sh
python3 scripts/test_sound_director.py
python3 scripts/test_media_workflows.py
python3 skills/motion-film-director/scripts/test_validate_delivery_report.py
python3 scripts/test-skill-links.py
python3 scripts/test_ui_design_director.py
node --test engine/motion-timeline-core/test/*.test.mjs engine/motion-audio-core/test/*.test.mjs
```

这些命令分别检查路由/工作流包内可达性、现有链接、UI集成回归与音频核心技术能力。它们不观看/听见影片，不认证授权或艺术质量。完整便携包测试另按 `python3 scripts/test-skill-package.py` 的依赖要求执行；依赖缺失记录 BLOCKED，不把只验文档说成完整包通过。

`test_media_workflows.py` 覆盖独立视频审核、音频审核、配乐生产的仓库路由、配置路径/源码排除，以及临时合成视频的解码与模型输入准备、真实候选生成→Audio Core 混音→PCM/AAC 解码、无 key dry-run。它不读取私人 `.env`，不调用 provider，不保存作品；真实听审、连续观看与音乐质量依旧未验。独立三个 Skill 通过构建器 `--media-skills` 与一份 Motion 依赖并列打包；另跑 `python3 scripts/test_media_skill_package.py` 验证真实解包路线，不把该测试称为宿主自动注册成功。
