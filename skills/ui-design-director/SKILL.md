# UI 设计导演 · 仓库内薄流程

本 Skill 是可读执行的工作流程，不是自动调度器。已有结构/契约检查，并曾在三轮真实固定画幅静态创作中使用；该轮次的总体作品质量未通过，不代表后来所有作品都被否决。单件或局部正向反馈也不证明整个流程提升设计质量；当前作品状态以其版本绑定的实际证据与用户反馈为准。不能将三轮静态任务计为同一对象的三轮视听验收，也不能宣称 Motion 集成已获完整验收。个案产物、评审与反馈保持私有，公开方法只保留有边界的可复用结论。

## 目标范围与已验能力分层

目标是独立 UI 设计导演，不只是一位固定画幅排版助手：可以规划用户任务、信息架构、页面/状态流程、反馈与异常状态、响应式布局及可访问性要求，也可以决定 UI 如何表达产品/品牌内容，并指导实现。

当前仓库可直接复用的已验代码主要是静态 Canvas 设计资产；这限制的是**可声称的实现和验收证据**，不是禁止提出交互/响应式设计。网页实现需另接真实浏览器/前端执行能力，并分别验证行为、键盘/焦点、视口与中断恢复。没有能力或环境时交付明确标注的规范/原型计划，不冒充可用网页；也不把缺少执行环境误写成已测试失败。

## 仓库入口与环境

本文件唯一维护于 `skills/ui-design-director/SKILL.md`，由仓库 `AGENTS.md` 与 specs 显式导航。`skills/` 目录存在不等于宿主自动发现/安装；无自动注册时直接读取本文件执行流程，不声称已调度另一个代理。先定位含 `SOURCE-SCOPE.md`、`engine/` 和 `skills/` 的实际仓库根，记录 commit；所有下列仓库命令从该根执行。源码、可执行环境和证据分别核实。

## 先确认入口与范围

- **用户直接委托**：完成其指定的 UI 设计、分析、复刻或局部修订，按目标分清规划、静态、可交互实现的交付层级。不因项目属于 MotionStudio 就制作视频。无需强制多个方向：已定方向沿用；用户要探索时，比较实质不同的信息结构或视觉概念。
- **Motion 导演委托**：接收原始 brief、目标画幅、相关镜头信息、已锁定方向与具体缺口；提供关键画面及交接数据。整片叙事、时序、运动、声音与视频验收仍归 Motion 导演。不要反向调用 Motion 形成循环。
- 已认可设计仅需小修时保留未受影响部分，不强迫重新设计。任务主要为角色/摄影美术时说明非 UI 范围；涉及交互或响应式时继续承担设计规划，并核实执行环境后指导实现，将设计建议与真实验证结果分开。

## 使用共享知识，不维护第二份正文

先读 [共享知识入口与环境可达性](references/shared-sources.md)，确认当前能读哪些来源。先从[创作参考图书馆](../../knowledge/design/library/INDEX.md)总索引→相关分类索引→具体契约/例子/反例阅读，由模型按本次内容分析比较并选择，不要求运行检索工具。内容决策、设计指南和静态合同按问题展开，再读完整作品和积木；不要以一个索引代替三个来源。共享资料不可达时明确指出缺项，仍可基于用户已提供材料作有边界的设计，不假称检索完成。

## 最小设计闭环

1. 从已有上下文提取受众、主信息、真实内容/数据、品牌意图、观看尺寸与硬约束；只问会改变事实、授权或重大方向的缺项。示意数据必须显式标示。
2. 原创或重大重设计先执行共享[参考发现→蒸馏→有意图组合](../../knowledge/design/reference-to-composition.md)：主动筛选相关优秀成品、实看跨例对照并提炼适用原则/反例，再决定本次组合与原创变形。本阶段以需求拆解→查积木及参考对象→融合创作→实作发现缺口→缺口驱动复刻学习/补充→验证再创作为学习循环，不将扩库设为每个任务的门槛。既定方向小修仅复核受影响关系；无参考或未实看须按该页保留缺口，不冒称研究完成。
   定构图前，也按用户要理解、比较、选择或执行什么，从[表达问题书架](../../knowledge/design/library/expression.md)选择相关决策经验，读其原文与适用边界后判断，不仅按行业名称或视觉风格筛选。对实际影响方案的经验，在已有设计说明中简述采用的关系及画面落点，或不适用的任务/证据原因；没有相关经验可说明缺口。不逐条审查全库，不要求采用某个案例，也不另建检查表。
3. 内容关系先于皮肤和组件：决定第一焦点、证据层级、阅读顺序及核心视觉概念；按共享流程先建立整体视觉锚，使品牌、色彩、比例、密度与外围界面系统和核心主物协同，再落实积木。ImageGen 可用于整体概念探索或素材，但须分清概念、素材、代码和已验证交互；用户要代码时不得用生成图冒充实现。复刻锁定来源/状态/画幅，不把优化版冒充忠实复刻。
4. 先验证主要体块、字级、色彩角色与信息密度，再实现细节。优先复用现有积木，但没有合适积木时不反过来扭曲内容。记录主张→各类积木职责→组合关系→真实代码调用/执行，明确采用与弃用理由，不以调用数量证明设计。实现可使用已有引擎，Skill 本身不附引擎、字体或素材。
5. 实看当前版本实际输出，核内容、比例、排版、颜色角色、来源与残差；对照参考所提炼的目标关系及必要的简化版，核本次变形是否改善表达；测量结果与视觉判断分列。若不能渲染/观看，交付明确标注为设计建议或未审候选。
6. 简洁交付用户要的画面及重要取舍；详细材料留项目目录。交付数据驱动实现时，按 [交接合同的支持域与依赖边界](references/handoff-contract.md#输入支持域与可视边界) 核合法变体、实际边界输出及依赖身份。需要 Motion 接续或可编辑复用时填写 [交接合同](references/handoff-contract.md) 与 [JSON 模板](assets/design-handoff.template.json)。不让归档或组件沉淀阻塞交付。

任务包含关键信息查找、局部修改/其余不变承诺、跨区域对象对应或容易误解的状态时，按需读 [任务焦点、跨区身份与状态语义](references/task-identity-state.md)。这是有限静态经验，不是强制模板。

## 检测只做辅助工作

按共享[检测工具的辅助职责](../../knowledge/design/reference-to-composition.md#检测工具的辅助职责)先定问题、可比条件、覆盖与反证。小差异不反推高吻合或好看；信号/声明检查与真实内容观察分列。本入口的 `scripts/check_sources.py` 只验文件可读，`scripts/validate_handoff.py` 只验交接结构；二者不看图、不核媒体字节、不认证审美。画面对照按[固定画幅合同](../../knowledge/design/static-ui-reference-study.md)保留原件、并排/overlay与局部差异，再核任务、文字、数据和状态；真实交互、响应式与键盘/焦点另实测。

## 每轮怎样指挥与收口

从共享流程的[逐轮指挥与反馈回流](../../knowledge/design/reference-to-composition.md#逐轮指挥与反馈回流)形成一条可执行任务：锁定本轮信息任务、保留项与最大风险，给出实际输出和复验条件。自行制作或委托实现都适用；不是启动代理的权限。参考拆解须落到本页某个比例、层级、对象关系或状态，积木选择须落到真实调用，不用“更高级/更丰富”代替决定。

先看整页及目标观看尺寸，再查最可能误读的局部；需要真实交互的任务另做行为验证。视觉方向已获有限认可时，保留其明确对象，仅修本轮可定位问题；若只是主图更好而外围层级变差，不把局部提升当整页提升。修订后对照同内容基线，决定保留、撤回或待验，不为满足轮数强加变化。反馈只更新相应范围，不能把“喜欢这个风格”写成产品可用或整套流程通过。

## 责任与变更

UI 层负责静态语义、视觉关系、对象身份和状态说明；Motion 层决定时序、转场、读时及声音。可指出读时风险，不预签视频通过。真实产品的状态变化需要事实依据；画出按钮不等于实现交互。

用户接受、静态视觉评审、技术检查、Motion 实测与发布权限分门记录。既有静态认可不外推为整片认可，用户认可不自动授予公开权。改动后仅使受影响的相关证据失效，记录新版本/hash。

在仓库根使用 `python3 skills/ui-design-director/scripts/validate_handoff.py <交接.json>`（独立复制时改用实际 Skill 路径） 按单一 DesignHandoff v0.2 检查资产/token/实现声明、消费回执引用与已有证据状态；现行模板同步采用 v0.2，旧记录保留而不自动改写。它不观看图片、不核媒体字节、不验证审美、不认证评审、不调度其他 Skill；输出有效不等于作品验收通过。

## 实作验证与迭代

用户要求真实 UI→Motion 端到端验证或多轮优化时，使用 [真实作品验证方法](references/end-to-end-validation.md)。结构测试、模拟请求、设计方案与真实作品通过分别计量；本 Skill 不附真实作品通过记录；验收以当前项目的真实证据为准。
