# 真实 UI → Motion 多轮优化验证

这是可复用执行方法，不是完成记录或持续授权。仅当当前任务明确要求端到端实作/多轮优化，并具备相应执行授权时适用。轮数、作品范围与允许的动作以当前任务为准；本 Skill 不授予视频制作、外部发布或未来任务权限。

## 固定实验对象与真实产物

选定一个有具体受众、任务、内容/数据依据的真实 UI 作品，再制作使用同一 UI 设计/状态的 Motion 作品。避免每轮换一个无关小样导致无法比较；不靠数量凑轮次。把原始 brief、使用情境、成功/误读条件及明确不可改变项冻结。用户已有选定作品则沿用，不另问方向。

记录本轮目标交付层级：静态 UI、可操作网页或应用。若为网页，必须有可运行地址/本地构建、真实操作录屏或浏览器测试证据；截图不能证明交互或响应式。Motion 必须是可播放的实际视频，不是分镜稿或仅有逐帧图片。具体时长按真实委托及现有 Motion 交付规范，而非为了测试擅自缩短。

依赖预检：源码/资产可读，字体与许可明确；静态/浏览器渲染工具可用；Motion 引擎和编码音频能力可用；实际观看/听审途径可用。阻断项记录 attempted/not_run/blocked，不用 mock 替代真实作品完成。独立草案不能据此假称这些依赖已附带。

## 迭代阶段，每轮真实闭环

|轮次|重点|必需证据|
|---|---|---|
|基线与首轮修订|完成 UI 与 Motion，识别内容、视觉、交互/状态、运动读时的主要问题并修订|首版与修订版实际产物、独立原始问题记录、源码/资产/成片 hash、复验结论|
|跨层优化|用第一轮实际结果修复静态→Motion 交接断点；核功能色/对象身份/数据同源、响应式或目标观看尺度|同任务前后对照，交接 manifest 与实际调用/偏离，相关 UI 与视频重渲染/回归|
|最终鲁棒性|对未解决问题进一步修订，完成连续观看/听审、关键 UI 任务与恢复路径，冻结最终版本|最终轮变更与复验、最终实际媒体、遗留问题、各验收门与权利状态|

每轮必须有一次证据驱动的实际修订和修订后复验；若没有合理改动，不为了凑数加装饰，说明该轮是未形成优化并寻找真实尚未覆盖的任务风险。多份计划、多次结构测试或复制同个视频不算多轮实作。

## 同一记录结构，区分五类证据

每轮记录：`round_id → brief_version → UI/Motion 源码与产物 hash → 观察方法与范围 → 问题/严重性/反证 → 改动 → 新 hash → 复验 → 未解决项`。

- 技术：构建、完整解码、依赖/字体、溢出、代码测试。
- 静态视觉与语义：实际目标观看尺度，主张/数据、焦点、字形、比例、材料关系。
- UI 行为（按真实交付范围）：主要任务、错误/空/加载状态，重复点击、取消/返回、中断恢复，目标视口及键盘/焦点。没有实现的需求列为未实现。
- Motion：连续常速观看、读时/对象连续性、真实因果；实际听审、声音职责与声画同步独立记录。按现有 Motion 导演的完整交付门执行。
- 用户接受与发布权：独立于上述证据；无法取得用户意见就保持待接受，不虚构批准。

独立评审先看 brief 与真实作品，再看作者解释。并排比较同内容/同目标尺度，避免将新字体或更长时长的收益错误归因为导演流程。可以判断改善、不变或退步，不以虚构总审美分掩盖具体问题。报告结构有效不等于作品成功。

## 交付与停止条件

交付真实 UI 与 Motion 产物，以及各轮简明差异/证据索引和最终分门状态。当前任务要求的各轮均实作并复验且无未披露阻断后才称所要求的轮次完成；部分门仍待用户接受时说清，不称批准最终版。若工具/素材/权限阻断真实制作，具体说明已完成什么与阻断动作，将所要求的实作状态保持未完成，不靠技能结构检查结项。
