# 进度界面短片：复用与收敛笔记

这是项目实现中可迁移的编排经验，不是新元素目录项，也不是普遍艺术效果的验证。先完成影片，再决定是否通用化；参数变体不新增 primitive。API 契约仍以[基础库](motion-elements.md)与包内验证器为准。

## 已使用什么，而非看起来像什么

| 层次 | 实际实现 | 不应宣称 |
|---|---|---|
| 已有 API 复用 | `sampleMotion` 的 `motion.transform` 驱动近景、全景和局部放大；`framesToTime` 提供帧到有理时间映射；`curve(smoothstep)`、`lerp` 负责插值 | 数学辅助函数是新动效；镜头参数是新 primitive |
| 已有构图复用 | 完整片源码调用 `offsetCards` 计算末段七卡目标布局 | 已使用 `focus-handoff`、`tile-signature` 或碎片重组配方 |
| 项目编排 | 屏幕标题、世界坐标面板、裁切、文字读时、卡片状态、按钮反馈与片尾收束 | 已新增通用时间线、任意路径 morph、局部揭示 API 或物理模拟 |

样片未调用 `offsetCards`，它只出现在完整片的末段实现。文字揭示使用 Canvas 矩形 clip 与位移，不是 `withLocalReveal`。项目曲线不应因相似外观被计成已调用的目录能力。

## 配方一：退镜完成后，再让细节可读

**问题：** 镜头尚未退回，先恢复数值/书名，会出现“标签已到、数字仍在画外”的短暂错误。

**做法：** 把镜头变换、屏幕裁切、世界坐标内容和屏幕标题分层。镜头先回到足够容纳关键文字的构图，再启动细节透明度；标题不继承世界镜头矩阵。不要只调整淡入而漏掉裁切边界。对近景→全景、局部放大→全景分别定义时间窗，不默认用同一参数。

**本次证据：** 样片修订后，实际编码的匹配时间帧中完整数值与书名恢复；另一退镜帧能够同时看到七卡。支持的是所查帧的构图/裁切改善，不能据此声称正常速度节奏或声画体验已验证。

**复用检查：** 查变换结束前后、文字淡入起止与中点，并检查实际编码，不只检查源 Canvas。多语言、更长书名或新画幅须重验。

## 配方二：共享状态源，不让画面各自编数字

用一个确定性的时间采样入口返回阅读状态：累计次数、累计页数、每日页数、按钮按压进度和时钟。累计值从已激活条目的数据求和，而不是独立 keyframe 一个“看起来正确”的数。

本次七条数据的六日/七日累计为 134/142。次数、总页数和进度条共用该状态；卡片仍从同一 `pages/on` 数据源独立计算激活与揭示。按钮和时钟由同一时间采样，但不是由累计次数因果触发。准确表述是**共享数据与时间源**，不是已经实现了一个统一事件状态机。

项目保留可重跑的十二时间点状态断言，覆盖累计次数/页数、七条数据和按钮反馈先于末卡提交；另做九个边界状态、反向/重复采样、按钮起峰止、末卡激活相邻帧的直接断言。它们支持数据一致性与无调用历史依赖，不验证渲染像素、真实用户点击或视听同步。

**下一次可抽取的候选：** 让显式事件表同时产出卡片状态、计数和日志反馈，并验证事件顺序/重复 ID/时间边界。当前只是可提炼方向，不是已入库模块。

## 配方三：七卡收束保留视觉身份，不冒充几何 morph

完整片源码把七个索引卡片映射到 `offsetCards` 的稳定 `day-*` 布局，插值各自的位置、尺寸和圆角，保留卡片配色、连接线及顺序，再揭示品牌文字。前段与片尾由不同绘制分支实现，交接处靠匹配几何建立连续性；上移采用项目私有的单调 Hermite 轨迹拟合，不是新增库曲线能力。

这是**项目级七卡→书签式卡组编排**，不是任意形状拓扑变换，也没有库级跨分支对象身份验证器。与已有 `tile-signature` 的“先归位、后署名”有叙事共性，但不使用 raster tile/UV；与 `focus-handoff` 的注意力交接相似，但并未调用该配方。优先保存项目参数与边界检查，不复制新配方凑数。

完整片已生成 720 帧并通过全量解码；获批样片对应的前 450 帧原生 PNG hash 全部一致。此回归保护已通过的前段，不声称有损视频编码像素相同，也不覆盖新增片尾。

独立评审实际编码的 503/504/505 帧（60 fps）确认交接附近七卡未丢失、未见硬跳；510/525/540 帧确认七卡重排/堆叠与蓝线连续，末轮文字裁切余量修复后，以实际编码的 564/570/600/719 帧复查标志、品牌字、完整副标题与结尾。该轮修订的原生 0–564 帧保持一致，仅调整 565–719 帧；获批样片对应前 450 帧仍无变化。证据是匹配 PTS 静帧和相邻边界帧，不是连续观看或通用对象身份验证。

迁移时仍须检查交接相邻帧、卡片数与层序、连接线连续性、文字留读。具体影片的完整视听验收状态以该版本交付报告为准。

## 生产反馈如何真正回到工具

- **AAC 尾段修复已有代码与回归。** 视听审查准备器不再用较长的容器/AAC 时长生成视频抽帧计划，而独立绑定音视频流的 duration ticks/timebase；视频采样严格落在视频流内，音轨完整解码、不裁尾。未知/不一致时长拒绝处理，旧 manifest 须重新准备。公开修复提交 `b4caa226735f19b49196f76fb37bfc6d41180f6a`；核心逻辑见 `scripts/audiovisual_review.py`。
- **本笔记复验范围：** `AACTailTests` 与 `StreamTimingTests` 两项离线测试通过，含真实合成 AAC 编码与独立完整 WAV 比对；未发起模型调用。该修复消除准备阶段错误，不证明模型审查成功或成片音画合格。
- **固定报告沿用现有实现。** [报告规范](audiovisual-report-standard.md)要求同一 JSON 生成 PNG 总览与 HTML；canonical `check_final_delivery.py` 已通过 `render_canonical_pair` 走固定模板。复用的是报告合同与生成链路，不是为每片另造一张报告；未听、未常速看、受阻必须保留原始状态。

## 收录与证据边界

本笔记新增的是可发现的经验指导；没有新增 core API、目录条目或 primitive。相机/揭示编排与共享状态已具有限定样片和函数测试证据；末段收束的实现与最终验收分开记录。通用化仍需其他内容/尺寸的迁移、非法参数和相邻帧测试，不能用一次用户批准推断所有场景适用。

公开材料仅保留通用文字与仓库代码指针，不包含参考影片、品牌截图、私人生产路径、密钥、供应商回执或交付包。具体影片证据留在其独立交付记录，不由本笔记替代。
