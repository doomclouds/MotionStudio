# 声音导演：先决定表达，再选择与制作

此页负责指挥与交接；[声音设计](sound.md)负责配乐/SFX、混音和技术边界，[主动寻源](sfx-sourcing.md)负责候选与来源，[视听审查](audiovisual-review-sop.md)负责证据。不要复制三套正文或另造验收 schema。仅安装 Motion portable 也可直接执行本页；仓库另有 `skills/sound-director/SKILL.md` 作为独立入口，不必启动额外代理。

## 1. 听懂委托，冻结基线

先从上下文写一句：`给谁听｜声音要让人理解/感到什么｜旁白/BGM/SFX/环境/静默各是否需要｜锁定画面与声音｜允许改什么`。配音不一定意味着旁白；无旁白的片子不为“完整”强加解说。

旧版更受认可时，先保留同版媒体、具体时间窗、用户反馈范围与来源。先问是素材选择、编排、表演、混音、同步还是播放问题，不从“旧版好”猜出频段或音符缺陷。参考原声只能在已有许可范围内分析/对照；可访问、用户喜欢或技术上能提取，不等于允许复用、上传或公开。不能把原声带给候选后称原创。

无法实际听到时，记录 **NOT_LISTENED**：只能提待验的结构假设、制作计划及授权范围内的技术草案，不宣称已识别听觉原因，不选“更好听”的胜者。现有波形、RMS、峰值与频谱不能补这个缺口。

### 合成前停点：先确认这次能听什么

在既有项目计划写清参考和输出各自的听审路径：实际可访问的音频/声画对象、执行者（人耳或原生音频模型）、方式/覆盖、权限与尚缺条件。浏览器打开播放器、下载成功、解码成功和工具已配置都不证明听到；文本模型读网页/乐谱/合成代码也不是听审。模型输入须真的包含音频并保留原始响应，仍不能替代常速声画观察或用户感觉。

- 能实际听：先完成下节的参考关系观察，再决定素材/合成；不把素材库搜索当成成品声音导演分析。
- 暂时不能听：明确阻断“参考分析完成”和“声音质量通过”，**不阻断技术草案**。可在原授权内制作有限的可编辑草案，标 `NOT_LISTENED` 和待验假设；不要无限合成/调参来替代缺失的听审。先告知缺口与下一步所需的试听对象/方式，不等做完才暴露。
- 用户要求“分析后再做”时，研究依赖的正式方向不能跳过；可独立验证技术链，但不能把技术草案当该研究已交付。需用户参与时给可直接播放的具体片段与一个判断问题，不把寻找参考和排查能力全部丢给用户。上传、付费或第三方服务仍单独遵守授权。

## 2. 参考发现 → 蒸馏 → 有意图组合

原创、新方向或重大声音重设计，先执行共享 [参考发现→蒸馏→有意图组合](../../../knowledge/design/reference-to-composition.md)；这也是声音导演的创作闭环，不只是一份素材采购表。先读 [创作参考图书馆](../../../knowledge/design/library/INDEX.md)，按表达缺口进入声音及必要的运动/作品书架，再读原始指导、契约、例子与反例。已有方向的小修只复核受影响关系，不强迫重新研究或多选曲。

声音分支按同一闭环工作，视觉/UI不适用的步骤略过：

1. **带问题发现**：从目标理解/感受出发，找能说明音乐发展、人声意图、事件反馈或声画留白的实际成品，不按风格标签、名气或库收录量选“优秀”。现有库不足时在授权范围寻找可靠原作者来源；未找到、访问/权利不足、缺听审分别记录。
2. **实际听与跨例蒸馏**：听完整段落及声画上下文，比较同一问题的不同解决办法和失败边界。记录来源/版本、时间定位、实际听到什么、解释假设、适用与反例；不要求固定数量。只有一个可听对象就保留对照缺口；仅有波形、文字描述或旧案例不能声称完成听觉研究。没有实际听审能力，声音原则只能作为待验假设，不绕过这个门。
3. **组合而非拼贴**：写出 `主张 → 音乐/人声/事件/静默职责 → 采用的参考关系与舍弃项 → 现有素材/准确API或自实现 → 本次变形 → 对照判据`。迁移的是句法、注意力或因果关系，不是未经授权复制旋律/录音。先定整体声音态度与段落发展，再挑音色；组合不必要就保留简单方案。
4. **真实制作暴露缺口**：用实际输出检验组合；区分选择不当、原则迁移失败、编排冲突、实现缺陷与缺机制。已有核心能做就改用法，不因试听未做而增加效果。真缺能力才在授权内补工具或带问题研究/复刻，回到当前作品复验，不把扩库设为交付前置条件。
5. **回流**：同画面比较目标关系，沿本页审核与既有私有 Case 保留采用、撤回和未验。沿共享流程的“实际取用→甄别→归位→新上下文验证”记录真实读取/调用、去重、权限与落点；无新增认识不添方法。研究路线被执行不证明声音效果提升，后续新任务仍须真实验证。

### 把听到的关系变成可复核选择

在同一项目的既有参考/决策记录补一行，不新增库或验收 schema：

`来源及版本/本地文件hash（取得后才填）｜参考时段与声画上下文｜听审者/方式/覆盖/原始证据位置｜可观察的声音与画面事件｜解释假设｜对照差异/失败边界｜本片采用/舍弃与目标时间窗｜权利范围/未决项`

观察和解释分开：先写声音何时进入/退去、音乐怎样发展、材质/距离/密度怎样变化、哪个动作有声或被留白；再推断它为何引导注意、制造预期或释放。拆清预备、运动、落定、余韵与音乐乐句的关系，不只写“高级、电影感”。只有画面实看时可写视觉观察；未听到的音色和节奏不填“观察”。参考源时码到本片时间的迁移必须明确，不能拿参考时间当成片 cue。

跨例比较同一个问题的不同解法，包含可保留的现有基线或不加音效方案；没有第二个可听对象就保留对照缺口，不强凑数量。对照用于选择职责/编排，不要求照搬曲风。可分析和可复用分别判断：原作品用于学习，不默认允许提取录音、复制旋律、下载、对外上传或随交付分发；素材复用另走 [逐文件寻源与权利门](sfx-sourcing.md)。无法取得授权媒体时保留来源定位及未验原因。

## 3. 先做声音脚本，不急着合成

在项目既有脚本/时间线旁补最少信息，不新建并行真源。使用实际秒段与原生帧/PTS，源时间与成片时间分开：

`时间窗/画面事件 → 观众注意或情绪 → 人声主信息/停顿 → 音乐乐句/密度变化 → SFX/环境或有意静默 → 声画关系 → 保留项/风险`

- 配乐决定动机、音区/织体、乐句、张力与释放，而非只改 BPM/音量。参考功能可迁移，旋律/录音不自动可复制。沿既有声音指导比较真正不同的候选；已获明确认可的曲目不强制重选。
- SFX 决定材质、距离、动作阶段和叙事意义。预备声可先行，完成声不能早报结果；不是每个转场都加 whoosh。环境声负责空间连续性，静默负责注意力或停顿，不默认填满。
- 人声决定谁对谁说、为什么此刻说、句中重点和情绪变化，按 [旁白与配音表演](voice-direction.md) 执行。没有旁白也必须留出视觉阅读时间。
- 声画关系可以同步、先行、延续跨镜、对位或留白，每次写明作用。不是所有剪切跟鼓点，也不是让字幕、重音、撞击同时抢焦点。
- 决定某一窗口的主次：人声承载新事实时音乐/事件退让；结果已经靠画面说清时可让声音只支持或静默。不要把全轨推响当清晰。

## 4. 以最小比较做决定

从最大风险选同一画面、同一时间窗的 A/B，保留可回退基线。纯音频任务改用同一时间窗、职责与播放条件，不要求额外制作画面。一次优先变一个决策（例如素材/表演方向，或单个事件平衡）；若必须联动则记录变动，不能假装因果已经隔离。对比不靠更响的一版取胜：记录播放增益、设备和响度差，必要时只在比较副本作响度匹配，不污染 master，也不把匹配当艺术标准。

实际听时先听完整段落，再听有问题的句/事件；分别核音乐发展、人声表达、事件职责、声画因果及整体空间。孤立 stem 可定位，最终仍要在画面与完整混音中听。短窗成立不代表全片成立；听不出可靠差别就保留原方向，而非为了迭代而改动。

### 让用户实际感受，而不是只看制作说明

当任务包含方向展示或比较，给同画面、同窗口的可播放候选/对照（纯音频用同窗口、同播放条件），先交用户要听的内容，再附一句“这次只改变什么、请判断什么”；不要只交混音术语或指标。公开/外发参考原声未获许可时不嵌入、不重传，可用合法原始播放入口与时间定位；自制候选按既有交付方式发送。确认交付的文件就是被审查的版本，无法播放或附件失败应报告，不能算体验闭环完成。

反馈记原话及其指向的版本/范围。不把有限接受当热情认可或否定全部合成音乐；用户能提供整体偏好，但未提具体原因时不可代写“音色太尖”等听觉诊断。将未决判断变成下一轮同窗问题，真实复听后才保留/撤回原则。未收到反馈保持待反馈，不自动新增版本、声称提升或晋级作品。

## 5. 按真实能力执行

编辑前读 [Timeline Core](../../../engine/motion-timeline-core/README.md) 与 [Audio Core](../../../engine/motion-audio-core/README.md)，渲染连接见 [引擎使用](engine-use.md)。本页是作者决策，不是可直接提交给引擎的新 JSON 字段。

- 按职责保留实际分轨（例如音乐/事件/环境/人声，按本片需要，不强凑轨数），记录每轨来源、生成方法或准确 API、参数、入出点及 cue。分轨便于定位和重做，不证明听感自然；先在全混音中判问题，再用 solo 查因。
- 现有核心可执行合法本地源的裁剪/移动/拆分、暂停续播、分声部路由、gain、fade 与显式线性幅度自动化；分轨和素材身份应随实际输出保存。
- 显式 gain 自动化可以安排人声窗口退让，不等于自动 sidechain ducking。无分轨不能声称单独调整原混音里的贝斯或人声。
- TTS、声线克隆、语音转录/强制对齐、作曲模型、EQ/压缩/插件、变速不属于当前核心能力。需要时先核外部工具与授权，按真实支持执行；没有就交付待录文本/方向或可用素材候选，不伪造音频。
- 混音核 clip → stem/bus → master 的职责。保留尾音和呼吸边界；对最终封装音轨重新测量与听审，不拿源 WAV 通过代替最终编码。

## 6. 交接与收口

需接续制作、可编辑源码或可迁移交付时，另按 [可重建交接](rebuild-handoff.md) 给出根绑定、完整命令、输入恢复与新目录执行证据；同机可读绝对路径不算迁移通过。

直接任务交付用户所要的声音/说明；影片任务将以下信息写入已有项目交接/报告，沿 [交付规范](audiovisual-report-standard.md) 的既有证据与状态，**不是新增验收协议**：

- 锁定画面版本/hash、时长/帧率；源音频与候选身份、时间映射及实际混音/导出入口。
- Motion 提供画面事件、原生帧/PTS和阅读窗口；声音返回该事件的角色、入出/尾音、静默与未验风险。UI 仅在界面状态、字幕或信息焦点冲突时确认语义，尤其不能让确认声早于真实成功状态。接收方记录采用/偏离与复验范围，不用三方交接文字代替实际合看。
- 采用/弃用的声音决策与适用时间窗；人声文本/读法、cue 职责、静默、关键入出点；必要 stems 和最终 master 的实际位置。
- 每个来源的许可证据、使用/同步/改编/公开范围与未决项；声音或肖像授权不从工具输出或素材许可证推定。
- 已执行的技术检查、实际听审（对象/范围/方式/设备/发现）、常速声画观察和用户反馈分别记录。模型意见说明其方式，不冒充人耳；无法听就是 NOT_LISTENED。局部通过不替代全长。
- 给接收方具体复验条件：例如修改某句后复听该句及前后乐句、检查对应字幕/结果时间，并重查最终混音/编码。换源、剪辑、混音、重编码后使受影响证据失效。

公开沉淀仅保留“在什么问题下选择什么、为什么、反例、未验边界”。真实媒体/参考原声、私人反馈与报告身份留在已有私有 Case；用 [知识工作流](../research/video-knowledge/WORKFLOW.md) 保留失败和撤回。某次旧原声更受认可不能推出“程序音乐都不好”或“全套声音导演已验证”。下一次要验证的是具体选择与作品，不是增加文档数量。


明确由用户或用户已批准作品合同指定的**无音轨整片**，按[无声适用性合同](final-delivery-evidence.md#明确授权的无声整片声音适用性不是听审豁免)提交同版授权声明；声音/声画同步记不适用，不伪造听审或空音轨。未提供明确授权、有音轨（包括静音音轨）或仅听审受阻时，原有有声交付门不变。全长视觉、技术和报告要求仍适用。
