# 从样片直接推进完整交付

本页约束交付顺序，不替代权利、技术、视觉、实际合听或用户验收。最小原则是**完整影片优先，短试只解决具体风险，不能成为反复交付的替代品**。

## 1. 先锁定完整目标与声音职责

记录完整片长、画幅、已定方向、原作范围与真实待定项。视听脚本和低成本全长animatic从一开始包含音乐结构、关键SFX或有意静默；不要等所有视觉/组件完成才考虑声音。已有有效脚本、预演和通过样片直接沿用，不为本流程补做仪式性产物。

## 2. 分清内部短测试与用户样片

- `internal-test`：局部实现、边界、性能或故障定位，可短于7秒；记录所检风险和结果，不计作品/用户样片交付。不能把实际向用户提交审核的样片改标内部测试来绕过门槛。
- `user-sample`：首次用户可见审核样片**至少7秒**，后续确需重新提交的样片也适用。须覆盖有意义的连续视听段和对应关键风险，不能用循环、静帧尾巴、减速或无关填充凑时长。7秒只是时长下限，不是内容通过。
- 原作或本次约定整片本身不足7秒：先明确冲突，取得用户对该短片/版本的**明确例外**；未获例外前不能提交不足7秒的审核样片，也不能擅自扩写、循环或填充原作。内部测试仍可继续。例外不自动扩展到别片。
- `final`：完整候选按委托的完整时长与内容交付，不套用样片7秒下限。把7秒样片改标final不能使不完整影片变成整片。

## 3. 样片通过即进入production

记录用户原话、对应版本/hash、获准范围及仍需保留的限制。样片在其范围内通过后，沿已定方向直接完成约定全长：接完全部镜头、转场、文字、BGM/SFX和收尾，再做全长自审。**不再把同一方案的不同长度小样逐个交给用户重复审核。** 已通过且满足下限的样片（例如8秒）不因新增流程重跑。

只有新的具体缺陷/未决风险才开对应内部短试；重大方向变化、用户明确要求的阶段门或新的权限需求才重新确认。局部修复按影响范围回归，不重开全部方案，不把“样片通过不等于整片验收通过”误读成不能继续生产。

组件通用化、入库、Gallery、知识记录与Skill修订另行沉淀，不阻塞当前完整候选；也不为了等待它们改做更多样片。

## 4. 全长视听审查与可视化报告一起交付

按[视听审查操作规程](audiovisual-review-sop.md)执行角色分工、完整观看/实际听审、事件精度复核、模型意见裁决及问题关闭；不只填状态或分数。

绑定实际编码/hash，检查完整时长/帧数/解码、目标尺寸文字、动作与交接、全长节奏、音乐结构和关键事件声画关系；正常速完整观看、实际感知听审与声画同步审查分别记录。实际感知听审可由真正接收并分析声音的音频模型或真人完成，必须诚实标明方法；纯文本模型、转写、波形/响度指标和音轨存在都不算听过。发现影响目标的具体问题先修对应范围并回归。技术测量、静帧和播放器ended不代填实际观看/合听；真实音频模型听审也不冒称人耳试听，更不能独立证明声画同步。

确实无法执行的检查写明`not_checked`、原因与影响，不伪造通过；保留工具自己的`not_reviewed/NOT_RUN/BLOCKED`等原始状态，不将失败或用户否决降格成“未验”。完成可执行自审后可提交**待审完整候选 + 可视化报告 + 明确未验项**供用户观看，不声称全验收通过。`NOT_LISTENED`绝不能映射为通过；不能把缺少真实听审的成片称为已完成视听验收的最终交付。报告必须包含同版成片身份、画面证据、三类感知审查、技术结果、问题时间窗和未验原因，不能只交一张绿灯表。若用户明确要求某检查通过才交付，须保留该明确门。OWNER接受在用户看过对应完整候选后记录，不是制作/提交该候选的前置条件；可选外部模型未获授权不阻塞本地制作或冒充已调用。

## 5. 本地样片时长检查

新用户样片提交前运行此检查，或复用同一媒体hash已有的有效视频流时长证据；不能只凭文件名或口述片长。已有通过且满足下限的样片不追溯补跑检查，不因此延后production。

仓库根（便携包从Skill根运行，去掉前缀）：

```sh
python3 skills/motion-film-director/scripts/check_delivery.py /local/sample.mp4 --role user-sample
python3 skills/motion-film-director/scripts/check_delivery.py /local/probe.mp4 --role internal-test
python3 skills/motion-film-director/scripts/check_delivery.py /local/complete.mp4 --role final
```

工具只用现有ffprobe读取**单一视频流**时长并绑定文件hash，不取可能被长音轨撑大的容器时长，不渲染、不联网、不安装依赖。优先使用`duration_ts × time_base`的有理数精确值，小于7不向上舍入；否则读取视频流`duration`，不对ffprobe已报小数再次舍入，但该回退受其原始报告精度限制。缺少可靠字段、多个视频流或文件变化即报错。此元数据检查不证明完整解码、无填充、内容完整、真实听看或审批；final仍须另核委托片长。

短原作例外使用`--short-original /local/original.mp4 --exception-record /local/exception.json`，仅适用于`user-sample`。记录字段必须恰为：`kind: short-original-user-exception`、`sample_sha256`、`original_sha256`、非空`user_quote`、非空`approval_reference`。两hash须匹配实际文件，原作视频流必须确实不足7秒；记录只保存真实用户授权，不让agent自行填写“同意”。工具只能验证声明结构与绑定，**不能认证用户身份或原话真实性**，输出`exception_recorded`及`authorization: declared_not_verified`，操作者仍须核对实际授权。

退出0仅表示时长门`passed/not_applicable`或已绑定例外声明；退出1表示样片不足7秒且无适用例外；退出2表示输入/依赖/测量错误。任何退出码都不是影片或艺术审批。**兼容保留的`--role final`仅表示样片下限不适用，绝不是完整交付门；完整片必须继续运行第6节。** 测试入口：`python3 skills/motion-film-director/scripts/test_check_delivery.py`。


## 6. 完整交付门：不能用时长绿灯代替视听审查

```sh
python3 skills/motion-film-director/scripts/check_final_delivery.py /local/complete.mp4 \
  --packet /local/review/packet.json \
  --report /local/review/report.html
```

工具使用已有本地`ffprobe`/`ffmpeg`核对单一视频流、单一音频流、实际帧数、视频时长和完整声画解码，在显式提供签名时以已有`openssl`校验签名，核验三类审查记录、证据和媒体hash，生成可视化HTML报告，并在stdout清单中输出报告SHA-256。无需联网、上传、安装依赖或付费调用。签名是可选的来源认证增强，不是生产前置条件。无签名但完整真实的审查记录与原始证据可满足声明式审查门，认证状态保留`declared_not_authenticated`；不能据此称已认证听审。若提供签名，则必须验证成功；可重复指定`--trusted-review-key`，只提供独立确认的审查者公钥，不从packet自动信任公钥。运行前准备见[交付证据合同与模板](final-delivery-evidence.md)。

| 层 | 必备证据 | 不能替代它的东西 |
|---|---|---|
| 技术 | 真实流信息、约定完整时长、全量声画解码 | 文件存在、音轨存在、容器总时长 |
| 视觉 | 完整覆盖的常速观看记录、时间窗观察、原生画面/接触表 | 只有抽帧、作者口述、播放器ended |
| 听觉 | 真人或原生音频模型实际感知记录、全长覆盖、可追溯证据 | `listened: true`、响度/峰值/频谱、转写、`NOT_LISTENED` |
| 声画同步 | 同版完整常速声画观看、关键事件因果/对齐观察 | 单独音频模型、稀疏模型抽帧AV、音频指标、时间戳接近 |
| 可视化报告 | 当前片hash、上述结果与局限、至少一份绑定画面证据 | 旧版截图、无版本报告、口头总结 |

- 退出`0`／`ready_for_owner_review`：满足本工具的技术与证据门，可提交用户验收；**不是用户已接受，也不是工具证明审美成立或确实听过**。
- 退出`1`／`review_candidate`：感知审查缺失、受阻、失败、覆盖不足或已提供的签名无效等，保留具体原因。只能明确作为待审候选交付，不能叫已批准最终版；失败不能降格成无害的未验。
- 退出`2`：输入、依赖或合同错误；修复后重跑，不从旧报告推定本次成功。

每份审查记录必须有`issues`数组：未关闭问题保持`pending`并阻断ready；只有`resolved`或`accepted`且附具体`rationale`才算处理完毕。方法局限写在`limitations`，不能用它隐藏未修缺陷或覆盖用户否决。

最终交付包同时提供成片、HTML报告及机器可读结果清单。报告hash由清单绑定（不做报告自hash循环）；报告内绑定成片与证据hash。任何成片、审查记录、证据或报告修改均需重新核验，不能沿用旧绿灯。版本身份匹配只证明字节一致；完整内容、权利与真实审查仍需负责的审查者核对。
