# 有引导的成片自审（候选工作流）

**入口先定目标，再挑方法，最后读取证据；不是把所有检查堆成一个质量分。**

## 1. 先写本片的检验问题

brief 用「给谁看｜想让他理解/感到什么｜可观察的成功条件｜反证｜当前版本」；选择 `--reference`（源窗/参考关系）、`--claims`（事实/图表证据）、`--audio present|none|unknown`。CLI 不假装理解自然语言：这些标志由导演按 brief 明确选择，默认音频未知会保留听觉门。每一方法的适用时机、输出、读法、误报、修正和复验都在机器可读的 [方法注册表](review-methods.json)。

仓库根目录执行（所有路径替换为自己的实际文件）：

```bash
python3 scripts/review_film.py plan path/to/final.mp4 \
  --source-root projects/my-film --brief '观众｜目标｜3–5个成功条件与反证' \
  --reference --claims --audio present
```

plan 只读本地文件并输出 JSON，不创建报告、不跑 FFmpeg、不联网、不听音频。`--source-root` 指仓库内项目目录：绑定其中 Git 非忽略文件（含未跟踪源码）的逐文件 SHA-256 与聚合 hash；成片另算 hash。这个**自审时源码快照不是“已证明该源码生成该影片”**；需要项目渲染 provenance 另证。未跟踪源码也纳入，但依赖、仓库外媒体、引擎等不在项目目录内的依赖必须由项目渲染报告另外绑定。不要拿 HEAD 一样替代内容一致。

## 2. 跑低成本本地技术层

```bash
python3 scripts/review_film.py run path/to/final.mp4 \
  --source-root projects/my-film --brief '同上' --audio present \
  --out projects/my-film/tmp/review/review-001

# 或复用这个真实影片已有的 motion-check；仍重算输入/工具/产物 hash
python3 scripts/review_film.py run path/to/final.mp4 \
  --source-root projects/my-film --brief '同上' --audio present \
  --reuse-motion-report projects/my-film/tmp/review/motion-check/report.json \
  --out projects/my-film/tmp/review/review-002

python3 scripts/review_film.py report projects/my-film/tmp/review/review-002/receipt.json
```

输出目录必须**尚不存在**且已被当前 Git 规则忽略；不会覆盖旧报告或改忽略规则。默认 run 只调用已有 motion-check（需已有 FFmpeg/ffprobe、NumPy/Pillow；不自动安装）。实际逐帧计数、时间戳、全量视频/音轨解码、低清 RGB 帧差/接触表、响度/真峰分别保留。已有报告须输入 hash 与检查器源码 hash 匹配，字段/关联产物齐全才可复用。旧报告的原始创建日期保留在原文件，复用不冒称重新执行。

`report` 再核当前成片、源码、引导工具/注册表及所有引用产物 hash，变化→`stale`，丢失→`missing`。源快照只覆盖选定项目根；若外部依赖/输入变动，须主动新跑并核渲染来源。修改方法注册表/工具后旧 receipt 会失效，这是保守的版本绑定。`passed` 只表示这一套本地技术步骤完整且没有其定义的发现；没有规范目标的 LUFS 是 `measured`，不是听感通过。

退出 0 表示计划成功或本地技术检查无阻断；**不表示完整自审通过**。退出 1 表示 failed/blocked/stale/missing；退出 2 是输入/配置错误。

## 3. 按候选时间窗做独立冷评，而不是相信热图

1. 先看 brief 与最终编码，后看作者解释；正常速度看完整声画，记录未看完范围。浏览器日志需文件 hash、播放器、速率1、静音状态、播放区间、ended/停顿/掉帧与实际听看者；decode 成功不能填写这项。
2. 帧差高峰/低谷只是复看线索：检查原生邻帧、同帧源片，排除切镜、设计静止、纹理、缩放和压缩误诊。4Hz 会漏单帧与短闪；不是光流/注意力/眼动。
3. 有相机冲击：两个固定世界锚共同位移/尺度 + 附属物/近远景/未拟合时刻。主体 bbox 不是相机证据。有操作：逐项预备→接触→结果→释放→恢复；读时在目标观看尺寸核。
4. 有来源片段/复刻参考：核 `media`/`evidence-bindings` 的源 hash、许可、原片窗口、成片帧号和精确对齐；可用下方 `compare` 采集明确配对的解码帧，不以近似 seek、平均 fps 或相似度代替语义对应。
5. 有声音：事件表标有声/有意静默，编码后逐窗听 BGM 掩蔽、心跳/biu 落点与层次。响度测量和事件数量不替代合听。
6. 查自己的项目 README 并运行实际源码测试，例如：
   ```bash
   node --test /absolute/path/to/your-project/test/*.test.mjs
   ```
   保存命令、退出码、测试数、范围、源码 hash 与日志。随机跳时/逆序、字体/文字、图表数值/投影、事件边界/中点/结尾各自记覆盖；旧9项通过日志不能自动背书修改后的源码。
7. 最小修复→同条件对照→相关窗+邻接窗+未拟合窗回归→重跑失效技术证据。用户否决方向时先改方向/材料/信息结构，不能以技术绿灯抵消。

### 参考/候选同条件对照（仓库本地入口）

`compare` 复用本入口的源码快照、hash、忽略目录与失效复核；**不**运行模型、不联网、不评分，不自动升级四个验收门。先声明哪些内容相同、哪些刻意替换，再指定时间配对：

```bash
python3 scripts/review_film.py compare path/to/candidate.mp4 \
  --source-root projects/my-film --reference-video path/to/reference.mp4 \
  --brief '要保留的关系与可见反证' \
  --pair 2=2 --pair 4=4 --pair 160/30=160/30 \
  --alignment-note '名义同起点；比较相同动作相位，不声称每个像素相同' \
  --text-font-differences '原创替换文案；授权替代字体；字形外框不可逐像素配准' \
  --reference-caveats '说明录屏卡顿/丢帧/裁切；未知就写未知，不能默认为无' \
  --audio none --extract-frames --out projects/my-film/tmp/review/matched-001
python3 scripts/review_film.py report projects/my-film/tmp/review/matched-001/receipt.json
```

时间为秒（十进制或精确分数），各自相对**首个解码PTS**。工具逐帧读取真实时间戳，选 `[当前PTS, 下一PTS)` 所显示的帧；记零起始解码帧号、原始PTS/timebase、偏离请求时刻的量，不由 `fps×t` 猜帧。缺失/重复/倒退PTS、末帧时长未知、越界时间均阻断，不悄悄落到最近可用帧。默认只存元数据/配对证据；`--extract-frames` 才顺序解码准确帧，写原始栅格尺寸PNG和本地并排HTML（不自动旋转、不缩放文件，查看器可缩放；解码PNG涉及色彩转换，不是原始像素或色彩一致性证明）。源/候选尺寸、SAR、旋转等不同须另声明和解释；本工具不替你自动裁切或配准。

成功 `collected` 只说证据已采集；退出0不等于技术/艺术/听审通过。缺文件、hash变化及必需证据缺失分别为 `missing`/`stale`；输出必须是尚不存在且已ignored的目录。`report` 复核源片/候选/源码/工具/证据并重算配对，不填人工门。`--audio` 未提供保持 `unknown`，缺少音轨不自动变成“有意静默”；轨道存在性与声明冲突会明列，任何情况都不声称听过。引用了带受限文字/图像的参考帧时，证据只留本地忽略目录，不复制到源码或公开交付。

**读对照时的两个易错点**：
- 替换字体/文案后，外圈字形bbox同时受大写高度、字宽、空隙与切向排布影响，不能据此断言baseline半径错。先核几何基线与字形度量，再看整体密度、层级和动态遮挡；活动态导航文字也要单独查真实背景对比，不能被主体大字检查覆盖。
- 录屏中的重复帧/停顿是采样证据，不自动是原作easing。若能核到原作解析运动，分开记录“运动模型”和“录屏相位校准”；不要为贴录屏卡顿把候选做成卡顿。明确实际保留的周期帧数/循环次数，完整时长不等于独特内容时长。

### 同格式视听基准与内容门

出现以下情况且有合法可用的本地源文件时，**必须先做双方同格式导出**，再解释差异：指定参考的视听复刻；用户明确要求基准/同条件比较；用户指出新版不如旧版；准备以“更像参考、节奏/声音更好”作为版本改进结论。入口为仓库 [`tools/reference-benchmark/README.md`](https://github.com/doomclouds/MotionStudio/blob/dev/tools/reference-benchmark/README.md)：原片/旧版与候选分别导出同 schema、配置、单位和 SHA/PTS，保留原始时间差，不用偏移或 DTW 隐去相位错误。此工具独立于 `review_film.py`，不会自动写入四门通过状态。原片不存在、无许可、依赖或执行受阻时记缺口；不得拿单边漂亮图表冒充已比较。

原创不是逐像素追随外部作品：按 brief 判断内容与体验；若用户报告退步，以相关旧版对照新版，并保留用户否决，不把旧的技术绿灯或局部赞同外推为新版成功。先诊断主张/动作/信息/声音哪里变差，再决定删减、回退或局部修改，不靠继续堆内容证明进步。

|准备作出的结论|除了低层基准，必须有的实际证据|
|---|---|
|材料、形状、层次、对象身份、阅读或动作关系接近目标|对应原生帧/ROI与连续动作窗的真实内容观察；涉及节奏/读时则以正常速度观看，不能只看缩略图或 SSIM。|
|选曲、音色、掩蔽、音效是否可辨、音乐推进适配|真实编码音频的实际听审，记录 hash、区间、方法与不确定性；波峰/onset/tempo/LUFS 不得代填。|
|声音与动作因果/落点成立|真实声画联合观察或适用且实际执行的 AV 方法，分列参考/候选的视觉时点、声音时点、双方相位差和内部 lag；音频单模态模型不认证 AV 同步。|
|叙事、信息结构、情绪或原创选择成立|按 brief 的完整内容审查与必要的常速声画证据；“更丰富”、更多镜头、低层相似或模型总分都不是内容门。OWNER 接受仍只来自用户实际反馈。|

人工实际观看/合听与模型辅助记录分列。模型必须真的接收相关媒体而非仅脚本/转录，并遵守既有单独授权、上传范围、费用和版本绑定；模型意见不是人耳体验或 OWNER 批准。未运行、受阻、缺失、过期一律保留 `UNVERIFIED / NOT_RUN / BLOCKED`，不得宣称相关门通过。报告按钮、mocked DOM 控件测试和数值夹具不能证明实际播放或听过；稀疏块位移也不是对象/相机分解，静态背景可能使中位数接近零。

后续内容审查的研究与事件契约见[中文研究说明](https://github.com/doomclouds/MotionStudio/blob/dev/reference-benchmark-research/content/RESEARCH.zh-CN.md)和[content-review schema](https://github.com/doomclouds/MotionStudio/blob/dev/reference-benchmark-research/content/content-review.schema.json)：区分 observed / planned / hypothesized，串联证据→差异→原因假设→建议→复验。现有[独立内容标注校验器](https://github.com/doomclouds/MotionStudio/blob/dev/tools/reference-benchmark/CONTENT_REVIEW.md)仅离线校验 schema、引用、媒体 SHA/时间窗并导出 HTML/JSON 注释报告，**尚未接入低层 benchmark 自动观察内容或听审**；退出0只表示契约有效，不证明注释真实、因果成立或作品通过。示例是合成格式演示，不能作为真实影片证据，也不替代上表实际行动。

### 2.5D资产接入与动作责任（仅在分层图像参与动画时）

关键资产以 `文件hash / 尺寸 / alpha范围 / 图层名 / 局部原点与世界锚 / 前后遮挡关系 / 允许运动` 登记。先在黑白或棋盘底检查透明边缘，标出背景中已烘焙的角色、桥、按钮和前景；需要独立变形/受力的物体必须能单独控制，不能把同一个桥或按钮同时烘在背景和动画层中。图像生成得到好的单帧不证明这些层已可用于动画。

抽查接入帧、动作峰值、接触/释放及一个未用于调参的时间：层注册是否一致、缩放/视差是否拆穿接缝、遮挡/阴影是否保留脚底与抓点。再核**状态因果**：谁主动做什么→接触/输入→桥/按钮/世界发生什么实际变化→释放/恢复；反应不能全是环境自己发生、角色被动被送走。漂亮关键帧和几何安全不会替代这项，长停留须服务具体观察/动作/阅读，否则回到动作与节奏，而不是堆通用UI装饰。

### 批准边界：只冻结真正获准的内容

把实际反馈记为 `用户原话 / 对应版本 / 明确认可范围 / 明确否决项 / 尚未表态`，并保留在自己的私有项目记录中。局部认可不得外推为完整作品批准；技术通过与艺术接受分开。

## 感官发布片的局部回归（有条件使用）

仅在 brief 以瞬时主张、视觉/感官与声音冲击为主时使用以下局部回归检查。它们是需要针对当前作品验证的诊断建议，不是跨片已验证规则；公开工具集不附私有任务复盘或委托反馈。

|适用条件与经验|具体检查|反例/边界|
|---|---|---|
|需快读排名：单主张不等于删比较|目标尺寸常速核谁领先、与谁比、差多少；停帧核同轴、配置/来源与选取口径|孤立No.1不能替代用户要的榜单；4行只是本片取舍，不是通用行数。|
|两个语义对象相接：各自留读，再做形态接力|分别计起点/终点可辨驻留；连看转化，疑点补原生邻帧，追身份、路径和落位|终点榜单可读不代表起点No.1读得到；指定碎片重组时，随机爆散后换图或整字晃动不算实现。无桥接需要时允许有意硬切。|
|要求可信平台窗口：比例与活动态一起核|同目标版本参考比标题栏、控件/边距、圆角、阴影、视口及主次；检查交叉过程|三颗圆点/蓝色粗条不等于窗口；不要求所有片都用Mac样式。|
|UI接成果：操作因果与遮罩/避让同验|逐段核输入→提交→反馈→转化→成果；密采移动文字、按钮和遮罩边界|按钮盖字、文字被裁切、结果先于操作均失败；示意UI接官方成果须标明非本次生成。|
|多窗换焦点但媒体应连续：分开两种时钟|记录布局与各素材源帧；测每次换焦点前/当/后帧，再看真实编码交接窗|布局平滑仍可能因相位取模而重播；有意循环/跳剪另标，不强制全片单调播放。|
|整体方向已认可：局部修复与不变范围一起验|冻结基线hash和允许变动窗；新旧同条件回归，比较未改原生帧/对应音频范围hash|全文件hash因编码改变不足以证明越界；局部好转不授权重排全片，范围不变也不证明审美成功。|
|有cue或音乐：落点测量与听感分开|先核事件职责、编码后时点/峰值/范围，再实际合听掩蔽与尾音；未听写未验|cue数量、音轨存在、PCM/包一致或模型标签不能替代听感；不要求每拍都加音效。|
|借外部素材或交付可复现源码：来源、复现、授权分列|核来源/版本hash；独立目录按合法输入恢复并记方法；另核修改/再分发权利|公开可见不等于许可，来源正确不等于本次生成，源码测试不等于独立复现；缺哪项就保留哪项未验。|

每个修复先在同条件旧/新窗比较，再复看相邻窗、全部受影响生命周期及一个未用于调参的时刻；源码/成片 hash 变化即重核相关证据。只有旧问题消失且未引入新的语义、遮挡或节奏缺陷，才关闭该缺陷。用户否决的具体项不能靠测量绿灯关闭；“整体已经ok”锁定方向，不自动批准尚未观看的新版。没有新的可证缺陷时停止扩大改动，保留真实未验门；经验回写为适用条件、反例和实际结果，而非成功宣言。静帧/密集帧仍不等于常速连续观看，未实际合听就记未验。 用户反馈可能揭示有限抽帧未识别的短暂主体或读时问题；保留已执行检查及其结论范围，追加反证，不以局部通过代替体验，也不倒写成从未检查。

## 4. 四个门分开，不自动填人工意见

当前 CLI 自动聚合的只有技术层；其余门有意保留未验，不接受任意 JSON 把它们升级为通过。人工记录单独保存到忽略目录，和 receipt 并读：

```text
方法ID / implementation（自动、人工、仓库外历史、unsupported）:
当前电影 SHA-256 / source snapshot SHA-256 / 记录时间 / 评审者:
目标 / 成功条件 / 反证:
实际方法与区间 / 是否正常速 / 是否真的听了声音:
证据文件及 SHA-256 / 命令退出码 / 播放器或工具版本:
观察 / 误报排除 / 修正 / 同条件复验 / 未验范围:
技术: passed|failed|blocked|stale|missing|not_run
视觉: reviewed|not_reviewed（说明范围；不冒充 OWNER）
原生音频: live_verified|not_reviewed（实调结果+范围；mock 不可填 live）
OWNER艺术接受: 明确反馈原话+对应版本 / not_requested / pending
```
