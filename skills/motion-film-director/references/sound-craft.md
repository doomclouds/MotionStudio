# 配音、配乐与音效：从叙事到可听交付

本页是[声音导演工作流](sound-direction.md)的工艺补充，不新增引擎、资产库或验收协议。先读工作流的听审能力停点；按问题读本页对应段，不把学习资料的结论写成自己已听过的经验。下文将一手资料中的原则转成 MotionStudio 制作建议，具体参数和例子均须在当前影片验证。

**自己处理声音，指自己承担声音脚本、选材/创作、表演指导、剪辑、混音与复验。** 可以使用明确授权的独立素材和现成工具；若任务指定原创配乐或自制音效，就按该范围创作，不擅自改用成曲。提取参考影片的整条混音、换文件名或只调音量，都不算完成自己的声音设计。没有旁白需求，不为展示配音能力添加解说。

## 1. 参考拆解：先听角色，再听做法

合法访问并确实能听的参考，按三个问题检查；不是必须另做三份报告：

1. **声画合看**：这个段落让观众知道或感到什么？主焦点是谁？哪些时刻声音开始、退下、转折或留白？先写观察，再写解释。
2. **声音单听**：关闭画面后，乐句是否仍有开始、发展与结束？哪些声音负责空间、动作、信息或情绪？记录可听事实和不确定处；混音中听不清的声部不能凭频谱命名。
3. **回到同版画面**：声音是在预示、跟随、延续还是刻意对位？静音比较可帮助区分画面本来传达的信息与声音新增的作用，不能只凭静音画面评价音乐。

Academy 的[声音与音乐教学资料](https://www.oscars.org/sites/oscars/files/complete_sound_and_music_activities_guide.pdf)采用声画分开再合看的练习，并把 Foley 定位为随画面表演的动作声音；这里只迁移观察方法，没有实际听审该资料提及的影片。

沿用项目的声音脚本，逐段补齐：

`时间窗/版本 → 观众状态 → 主焦点 → DX人声 / MX音乐 / FX动作 / AMB环境职责 → 音乐段落与声部变化 → 关键锚点/尾音 → 为什么有声或静默`

这是听觉分层，不是宣称已获得干净分轨。原作仅有混音时，保留“推测的职责”；即使用分离工具取得估计声部，也不能称原始 stems、证明无伪影或扩大使用权。可复用的是节奏关系、留白、配器职责，不是默认可复制录音、旋律或声标。

## 2. 配乐：先写整段形状，再写音符

Berklee 的[叙事分析课程](https://college.berklee.edu/courses/fs-510)把叙事意图、与导演协作、音乐入出点及音乐功能放在配器与风格选择之前。这里落实为先做一张短段落表，再开始选曲或写谱；课程说明不是对下列配方的效果认证。

### 选曲与原创的共同判断

- **叙事态度**：是探索、犹疑、持续推进、松一口气，还是有意与画面对位？避免只写“燃”“高级”。相同 BPM 不等于相同推进感。
- **发展空间**：候选是否有足够长的乐句、可编辑段落、高潮与结尾？先看全片能否成立，再裁一个好听的开头；不把短循环反复铺满当完整结构。
- **信息空间**：有台词/密集文字时，旋律、密集打击和持续明亮音色会不会争夺注意？先改变编排，不默认靠音量压低一切。
- **可用输入**：拿到的是整曲、真正 stems、循环、MIDI/谱面、采样器，还是只有混合 AAC？先核实际来源与权利，不能用文件扩展名推断可编辑程度。

没有现成合适曲目时，可比较不同音乐态度，或同一原创动机的不同织体；已有方向可靠时不强制另选三首。比较方法沿[同画面 A/B](sound-direction.md#4-以最小比较做决定)，响度匹配只用于比较副本。

### 原创短片配乐的可执行步骤

1. **决定何时不作曲**：标出有意无音乐的窗口，以及需继续承担空间/尾音的其他声部。静默是编排选择，不是遗漏。
2. **写最小动机**：先用单一音色写一个短旋律、节奏型或音色手势，让它有可辨认的轮廓；非旋律音乐也可用节奏/音色作为身份。先能说清它代表什么，再加层。
3. **分配声部职责**：例如低音支撑、和声/持续音承接、脉冲推进、动机聚焦、过渡连接。只保留本片需要的层，不把全部音色同时铺满；角色相同的层要有保留理由。
4. **让重复发生变化**：保留动机身份，按段落改变音区、音长、休止、配器或和声支撑。先选一项变化并试听，再决定是否联动；不是每到新镜头重启一个循环，也不把加鼓/加响当唯一升级。
5. **安排张力与释放**：先确定结果揭示/情绪转折，再尝试延后解决、减层、移开脉冲或扩展音区。和声、调式和配器的情绪作用依文化与上下文而变，不写“大调必快乐、小调必悲伤”的硬规则。
6. **做真正的收尾**：给乐句落点、声部 release 与空间余韵留时间。写清最后一次激发、实际声音结束和影片结束三个时刻；全轨淡出不是所有结构问题的补丁。

程序制作仍要保留谱面/事件及实际渲染参数、版本、采样依赖和分轨。固定 seed 只能帮助同环境复建，不证明原创权利、音乐性或跨运行时字节一致。采样器/乐器库的许可与代码许可分别检查。

### 拍点服务画面，不支配全部画面

先标少数必须支持的叙事锚点，再决定是否采用稳定拍网。若 BPM 以四分音符为拍，拍长为 `60 / BPM` 秒；其他拍单位须另写。用该关系检查乐句与锚点是否相容，不反复修改 BPM 逼所有 cut 落整拍。可采用弱拍/切分、延长尾音或有意不强调，仍须合听。

剪现成曲优先沿真实乐句与相容的和声/节奏位置，比较连接前后的完整上下文；交叉淡化只处理接缝，不修复错拍、错和声或剧情提前解决。保持原语速/音高还是使用变速工具必须明确，Audio Core 当前不实现 time-stretch。

## 3. 配音：从说话意图到可选 take

表演脚本和权利沿[旁白与配音](voice-direction.md)。制作时用以下顺序，不把换声线当唯一改进：

先核已有能力，不仅查独立命令是否在 PATH，还查已安装宿主的实际功能清单、版本/构建选项和本地模型/音色。例如 FFmpeg 的可用滤镜取决于构建；发现可用功能后，用非个人短句做离线探针，核返回的音频格式与时长再决定接入。工具存在、探针成功、授权范围和自然度是四个不同结论；不因探测缺项擅自安装、下载声音模型或读取云服务密钥。

1. **口语化校稿**：按句子意思划意群，检查专名、数字、单位、多音字、缩写和中英混读。画面显示文本与实际读法分开保留，不让发音替换污染字幕或改变事实。
2. **给行动指令**：例如“把刚发现的结果告诉同伴，先确认，再邀请继续”，并指出主要重音和情绪转折。少堆相互矛盾的形容词；同一文本比较不同表达意图，不只比较男女声或音高。
3. **先试高风险句**：选择包含专名、数字或情绪转折的短段。分别核读法、意思、停连、尾字和角色关系；记录采用哪个 take、为何舍弃另一个。没有听审时不能选“自然”的胜者。
4. **按完整意群生成/录制**：保留前后语境，不逐字拼接。长段可分句段取 take，但接缝要检查音色、距离、情绪与呼吸连续性；生成失败先修文本/发音/表演约束，不无限重试抽取好运。
5. **校时但不挤压**：用实际人声标语义锚点。超时先检查冗词、停连、允许调整的画面留读与重录选项；禁止为了塞时长把整段大幅加速、吞尾字或删掉必要呼吸。
6. **保留干声与处理版**：先修明确的点击/爆破/噪声，再按需要做温和动态和频率处理；试听处理前后，避免降噪水声、齿音处理造成含糊、门限截断尾字。未做的处理不记成已执行。

[ElevenLabs 的官方最佳实践](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices)说明发音、文本规范化、停顿与情绪控制依赖模型；例如当前文档明确部分模型不支持 SSML break。迁移原则是核**具体模型**支持的参数/标签，先试读再使用，不能假定同一 SSML 或情绪标记跨供应商通用，也不据本页假称已经接入该服务。模型/音色/文本/词典/参数和最终文件要可追溯；生成语音不冒充真人实录。

若录真人，先处理房间噪声与反射，固定话筒、说话距离和方向，试最强一句并预留余量，再正式录。防喷罩或略偏轴可帮助控制爆破音，距离也改变近讲效应与环境比例，不能给所有话筒套一个厘米数。[Shure 录音话筒技术指南](https://content-files.shure.com/Pubs/microphone-techniques-for-studio-recording/microphonetechniques-recording-guide.pdf)提供相应原理与摆位示例；实际以所用设备和试听决定。录音/生成、个人声音使用、外部传输与服务付费各按具体授权，不因“自己处理”而自动放行。

## 4. 拟音与 UI 声：给动作塑形，不给镜头贴标签

先写 `什么物体/状态 → 做什么 → 速度/重量 → 距离/空间 → 观众需感知什么`，再选择实录、合法素材、合成或组合。Foley 是跟随动作的表演，不是“搜一个脚步文件放进去”；可直接在同画面下表演并保留接触点、力度变化和停顿。

- **头**决定接触或启动是否明确；**身**承担重量、材质和运动；**尾**交代空间与结束。可以只用一个素材，确有缺口再叠层，避免每次都叠成爆炸。
- 相同动作保留声音家族，变化受力度、材质、距离或角色驱动。重复素材可采用有限、显式变体；变体身份与cue写回时间线，不能每次渲染暗中随机改变。
- UI 声先按输入、确认、失败、完成等语义分工，再定响度/音色层级。短键反馈不冒充发送成功；高频重复动作不能与关键结果等权争抢注意。
- 动作很小却声音巨大、远景却极干极近、材质切换但音色不变，都可列为待验证的错配。风格化夸张可以成立，但要有表达理由，不把拟真当唯一目标。
- 环境负责空间连续性，需解释跨镜头是否保持；切画面不必切环境。有意断环境可制造主观感受，但须区分环境退出、音乐休止与全混音静默。

[Apple 的音频与触觉设计讲座](https://developer.apple.com/videos/play/wwdc2019/810/)强调因果、协同与实用性，并比较确认反馈的不同力度。这里仅迁移“动作原因清楚、表达程度恰当”的原则，不复制系统声标，不把触觉参数当音频参数，也没有实际听过其视频示例。

## 5. 同步：对齐感知锚点与语义，不只对齐文件头

由 Motion 提供同版实际帧/PTS、接触/落定/结果时刻和容许窗口，声音导演回写目标音频锚点。某个声音在文件开始后才形成主要瞬态，裁剪后该偏移也可能变化；要对齐所选起音/瞬态而不是文件零秒。渐强、预备声和跨镜尾音可有意先行或延续，但完成确认不能在事实发生前误报完成。

定位示意：若裁剪后的声源主要瞬态位于 `a` 秒，目标接触时刻为 `t`，初始摆位可试 `t - a`；这是作者定位方法，不是感知同步通过。负入点、超出范围或改变裁剪时重新处理，不能隐式截掉攻击或尾音。尾音可以跨镜，不能为“整齐”逐帧硬切。

时间表、渲染帧和真实音频必须来自同版时间映射。CFR 用有理帧率换算，VFR 读实际 PTS；从绝对时刻一次换算到采样位置并记录舍入，避免逐拍/逐帧累加取整造成漂移。先核数据消费，再在最终 MP4 常速合看；逐帧统计或候选起音差不能证明感知同步。具体检查沿[声音设计](sound.md)与[视听规程](audiovisual-review-sop.md)。

## 6. 混音：先编排和增益，后修补

按实际需要建立 DX / MX / FX / AMB 分路，不强凑四条；保留干声和加工链。iZotope 的[视频后期流程](https://www.izotope.com/community/blog/mixing-audio-for-video-part-2-audio-post-production-workflows)建议按人声、音乐、效果管理子混音；[掩蔽教程](https://www.izotope.com/community/blog/unmasking-your-mix-with-neutron)也提醒编排本身可以减少频段冲突。以下是本项目的诊断顺序，不是固定插件链：

1. **先选可信声源**：坏读法、错材质、剪错段不能靠均衡器救回来。若源有明显缺陷，比较重录/重生成/换素材与修复成本。
2. **先让主角成立**：人声片先建立自然可懂的人声，音乐主导片先保留音乐段落形状，再加必要 FX/环境。优先确定“这一刻听谁”，不是全片固定某类永远最大。
3. **用编排解决争抢**：移动无语义绑定的点缀、删重复层、换音区/音色、给重要字或结果留空，再考虑推响。不能为躲开台词而移动必须与动作同步的音效。
4. **局部增益与自动化**：先处理 clip，再调 stem/bus，最后才整体 master。音乐退让应覆盖句意和呼吸边界，回升要听是否抽吸/抢尾字；显式增益包络不是自动 sidechain。
5. **仍需处理再用 EQ/动态/空间工具**：先明确要解决的频段冲突、刺耳、动态或距离问题，比较旁通与处理版。高通、压缩、去齿、混响与限制器无全片通用参数；不用过量处理抵消错误编排。
6. **核全混音再核交付**：solo 只定位问题，恢复所有层再听。单声道/小扬声器检查关键内容是否丢失或被遮住，耳机另查刺耳和不自然声像；少听一次不自动算全设备通过。

Audio Core 现有能力仅为其[实际合同](../../../engine/motion-audio-core/README.md)列出的本地源编辑、路由、gain/fade/线性幅度自动化等；EQ、压缩、sidechain、混响插件、time-stretch、TTS、作曲与自动强制对齐均不能凭本页文字调用。外部处理需先核工具和权限，保留输入/输出身份及参数，再作为新的真实源回到时间线。

## 7. 质量标准：技术、听觉、声画分别回答

先确定目标交付平台的当前要求，记录声道、采样率、编码、响度/真峰值目标及测量器。内部 Audio Core 使用 48 kHz，不因此推断任何平台都要求同样格式。EBU R 128 v5.0 的节目响度目标是 −23 LUFS，另用响度范围与真峰值描述；它是特定广播体系的规范，不能把 −23 或网上常见的 −14 LUFS 当所有短片的通用目标。[EBU R 128](https://tech.ebu.ch/publications/r128)

**技术层**复用既有工具核最终封装中实际选中的音轨、时长/偏移、解码、声道、峰值与响度、意外静音、切点/尾音及源身份。源 WAV 通过不等于 AAC/MP4 通过。测量没有执行就是未验，不能填零；符合目标也不等于好听。

**听觉层**必须实际访问声音。先常速完整听，再回问题窗口；同条件 A/B 不先告诉听审者哪版应更好，尽量控制响度差并记录播放条件。针对表达提出问题，不做空泛“高级感打分”：

- 关键事实、专名和句意能否一次理解？表演的重音和情绪是否符合人物关系？
- 音乐有没有保持身份又产生发展？转折、连接和结束是否支持叙事，而非机械循环或逐章重启？
- 必要动作反馈能否在全混音里辨认？重复音是否疲劳？有意静默是否仍有意义？
- 主次、距离、材质和空间是否一致？有无听得见的爆音、硬截、齿音、抽吸、失真或处理伪影？

**声画层**常速看完整同版成片：信息和完成状态有没有提前被声音泄露，声音是否指向正确动作，字幕/人声/音乐/SFX是否争抢，片尾是否有消化空间。音频模型的分段意见、数字对齐和人耳局部听审都不能冒充全长连续声画通过。

ITU-R [BS.1116-3](https://www.itu.int/rec/R-REC-BS.1116-3-201502-I/en)专门讨论音频系统小损伤的主观评估，不是电影叙事质量评分法；本页的制作听审也不宣称符合其正式实验条件。缺真实音频输入/试听时继续记录 **NOT_LISTENED**，可以交可编辑技术草案，不能选择“更好听”的胜者或宣布掌握了作品效果。

## 8. 自描述、交接与积累

项目层在已有决定卡/时间线/报告保留：声音目标与段落、采用/弃用的理由、真实台本与take、源/分轨/master/最终MP4身份、精确时间映射、实际生成/编辑命令、处理参数、复验范围和未决项。修改音乐、台词或画面时标出影响的句/事件/段落并复听上下文；全局处理或重新编码则重新核最终成片。

独立复用声音沿[Sound Elements](../../../engine/sound-elements/README.md)现有 `asset.json` 合同保存意图、适用/反例、来源、许可、生成入口、格式/时长与循环边界；不在本页造第二套库存或“已听”标签。真实反馈、声音身份和媒体留在授权私有项目，公开只放去素材化方法/审定代码。

逐件区分作曲/词、录音、表演、采样和生成服务的许可，以及同步、改编、商用、署名与独立分发范围。CC 官方 FAQ 明确音乐与移动画面按时间同步在 CC 许可下构成改编；ND 许可不能因“音乐本身没剪”就视为允许分享配乐影片。CC0 或其他许可也不能自动消除人格/隐私等第三方权利。[Creative Commons FAQ](https://creativecommons.org/faq/) 不明确的使用先停在私有候选，不把“免版税”“代码MIT”或hash当完整授权。

Motion 锁画面与叙事锚点，声音导演负责声音选择/表演/编排/混音，UI 负责必要的状态语义与字幕可读性；接收方按自己领域复验，不互相代签。最低可编辑交付是实际用到的台本/谱面或音乐事件、源权利说明、cue/混音入口、必要 stems、master 与最终文件，加分开的技术/听审/同步状态，不用参考整混音替代缺失工作。

### 每片只带回可证实的教训

开始选一个实际薄弱点，例如“动机没有发展”“旁白转折太平”“键入在音乐里被遮住”；写旧版问题、最小改动、预期和可能反例。结束保留同版对照与真实观察：修了什么、没有改善什么、下一种情境能否复用。参考学习、方法落地、技术通过、作品听审与长期能力提升是不同结论，不以文档数量或一次好评代替持续实践。
