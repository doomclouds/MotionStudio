# 内容到 Motion：UI 表达的专项迁移假设

从原 CONTENT-DECISIONS 指南分离，通用决策见[共享内容指南](../../../knowledge/design/CONTENT-DECISIONS.md)。这是 Motion 专项唯一正文，不要求直接 UI 委托进入视频制作。

## Motion 专项示例：按信息任务选择，不按行业硬套

以下表格保留原视频迁移假设，不是所有直接 UI 任务必需的制作阶段；UI 可以使用其中信息关系，但不能继承未执行的视频验证结论。

| 内容/主任务 | 候选 UI 结构、风格与密度 | 动作承担什么 | 不适用/证据门 |
|---|---|---|---|
| 数据趋势、方案对比：看出差异 | 同口径并排或单图逐层解释；中性容器，色彩只编码有证据的系列/状态；只露出当前论点所需指标 | 先建立共同尺度，再引导焦点；数值与图形同源，不为动效改数据 | 无真实数据、口径冲突、情绪叙事不强加 dashboard；[ui-001](../../../knowledge/design/cases/ui-001-dashboard.md)只支持 S，动作是 H |
| 工具/仪器教学：理解控制关系 | 按功能邻接的模块；角色色跨模块一致；一次聚焦一个输入及其可解释结果 | 保持控制对象身份，引导输入→结果；未知映射不画成真实因果 | 无真实交互/DSP 数据只能标示意；[ui-002](../../../knowledge/design/cases/ui-002-instrument.md)只支持 S，因果/音频是未验 H |
| 流程/产品讲解：知道下一步和状态变化 | 序列、少量步骤或局部界面；主动作与反馈层级清晰，辅助信息渐进出现 | 状态交接与焦点接力，而非整页同时飞入 | 真实产品不可伪造功能；长页缩成一屏无读时应拆镜；尚无本库对应静态/视频实证，仅 H |
| 复杂系统/概念解释：理解依赖 | 节点/连线或分层模块，显式图例，控制每镜关系数量；不因“科技感”增加装饰指标 | 依次揭示因果/依赖并保留已建立关系 | 连线不等于因果；无依据不生成因果箭头；仅 H，先核语义再选几何 |
| 情绪、人物、品牌故事：形成感受或记忆 | 可能不需要 UI；主体/影像/少量文字优先，界面只在故事需要时出现 | 服务主体、停顿和节奏，不强行套卡片或仪表盘 | 无信息任务就不选 UI 方案；写实光影/材质/复杂运镜不能假定当前引擎能做好；仅 H |

现有静态案例不证明视频有效；只有当前版本实际制作、常速观看并核对理解目标后，才可为相应范围记 V。技术、听审、用户艺术接受和发布许可仍分别判断。
