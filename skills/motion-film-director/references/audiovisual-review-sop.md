# 视听审查操作规程：先观察，再核证，再裁决

本规程用于每次实际完整候选；不是分数表，也不声称任何影片已经审过。样片获准后直接完成整片，审查内部执行，不把用户变成逐段审批员。实际媒体、参考、原始模型回执和会话记录留在私有项目。

## 角色与执行顺序

- **制作者**冻结编码、brief、获准样片范围、完整片长、必要主张与参考保留项；不得先把解释或期待结论塞给冷评者。
- **视觉审查者**实际常速看完冻结编码，再用原生帧/密集时间窗定位问题；可与听审者不同，必须真实记录身份与方法。
- **听审者**是实际听到最终编码声音的真人，或真正接收音频的原生音频模型；不把测量器、转写器当听审者。
- **声画审查者**实际常速合看完整编码并检查事件关系。单独音频模型或稀疏视频帧不能承担完整声画通过结论。
- **裁决与交付者**核对观察、输入来源、影响和反证；关闭问题后运行交付门，提交成片、可视化报告、结果清单。签名可选；来源认证与感知事实分开。OWNER仅对其实际看过的版本表示接受。

同一人可兼任角色，但不得把自审冒称独立审查。缺某项能力时保留该门受阻并输出待审候选，不填假角色、不为填表改写方法。

| 顺序 | 输入 | 必做动作 | 输出 | 未完成时 |
|---|---|---|---|---|
| 1 冻结 | 当前委托、最终编码、合法参考 | 核完整片长/画幅/版本、媒体SHA-256、素材使用范围 | 冻结清单、目标与反证 | 身份不清先阻断，不能用旧截图 |
| 2 技术预检 | 冻结编码 | 实际流/帧数、视频时长、全量声画解码；编码后响度/峰值另测 | 工具输出及hash、错误日志 | 修复解码/流问题再审；测量通过不填听审 |
| 3 冷评视觉 | brief与真实编码，后提供作者解释 | 常速完整观看，先描述所见，再定位读时/动作/转场/收尾 | visual记录、全长coverage、时间观察与原生帧 | 抽帧只能作诊断，不能填normal_speed_visual |
| 4 实际听审 | 从最终编码得到的声音及可追溯映射 | 全长感知，标音乐结构、声音职责、掩蔽、失真、疲劳、结尾 | audio记录、真实会话/模型回执、未确定项 | NOT_LISTENED保留；没有声音输入的模型不能过门 |
| 5 常速声画 | 同版最终编码与关键事件表 | 全长合看；逐项核声音与视觉起因/后果及有意静默 | av_sync记录、事件对应与误差窗 | 稀疏帧不够，标待审并补常速合看 |
| 6 核证与修复 | 三类观察、原始证据、目标 | 对质疑取同版同PTS证据；裁决、修复并回归 | issues处置依据与新版本记录 | 未关闭问题阻断ready，不藏进limitations |
| 7 报告交付 | 当前有效记录与画面证据 | 运行完整交付门；打开HTML检查图片/时间/状态 | 成片+HTML+机器清单 | 错误或候选如实标记，不宣称已批准 |

## A. 冻结、参考与时间坐标

- [ ] 记录当前成片hash、约定完整时长、真实流信息、实际帧数、帧率/时间基；变帧率片不得只用`帧号÷名义fps`推算时间。
- [ ] 使用参考前记录来源、授权/使用边界、原始文件hash；不能将可观看等同可分发。报告不公开附带未获许可的参考媒体。
- [ ] 帧证据带原生PTS、帧号及提取方法。若做裁剪/变速/偏移，记录映射；准确seek与近似seek分开，不把近似时间说成精确帧。
- [ ] 对照原片/旧版时明确同PTS比较，或显式列出不同剪辑的事件对应。不能随意挑“最像”帧冒充时间对齐。
- [ ] 关键姿态、动作接触/释放、转场起止和停留结束取边界前后帧；低频总览只定位，不排除单帧错位/短震动。
- [ ] 参考有录屏缺陷、文案/字体替换或不明时间映射时保留说明，不用缺陷复制或统计相近证明忠实复刻。

## B. 视觉：完整观看后逐窗核对

先不给制作者解释，审查者用自己的话记录观众会看到什么。再逐项检查：

- [ ] 目标尺寸下主体、手、对象、文字能看清，读时足够；结论/操作结果是否有稳定留读。
- [ ] 动作链有预备→接触→受力/操作→实际后果→释放→恢复；UI状态和操作结果一致，不靠对象消失伪造完成。
- [ ] 主体形变、世界相机和屏幕UI分开。震动/推拉疑点至少追踪两个独立固定世界锚，不只看主体bbox。
- [ ] 转场、景别和节奏服务信息，不用特效数目充当质量；全长开头承诺与结尾兑现一致。
- [ ] 每个具体缺陷记录时间窗、可观察反证与目标影响，附当前hash原生帧。误诊要撤回并留依据，不默默删掉。

输出`visual`记录：`normal_speed_visual`只能用于实际完整常速观看；密集帧观察在证据里按真实方法注明。至少一张报告图片同时列入visual的`evidence`，避免报告图片与评审版脱节。

## C. 听觉：感知与指标分轨

- [ ] 输入来自最终编码，不拿混音前WAV替代AAC；若抽取/分段，保存最终电影hash、提取方法、音频hash、起止偏移与重叠。
- [ ] 分段覆盖并集包括整片，头尾与连接处均听到。模型能力不覆盖立体声、长上下文或某类声音时明确记录。
- [ ] 先描述实际听到的内容，再核关键声音职责：BGM是否压住SFX、冲击/扫频是否分离、是否有突兀断音/噪声/失真、节奏与结尾是否成立。
- [ ] 每个观察带时间窗；听不清、缺失或无法判断必须保留，不按脚本补写声音。
- [ ] LUFS、真峰、波形、频谱、onset等只作工程/定位证据；另列实际听审记录，不能由指标生成“听过”布尔值。
- [ ] 真人记录保留实际会话与覆盖；模型保留真实音频输入身份、模型/调用信息、原始响应和提取映射。授权和费用由既有许可约束，不默认上传。

模型的“存在/不存在/掩蔽/失真”均是待核观察，不是自动审批。制作者或裁决者复查原声对应窗口；不能仅因provider回执有效就接受结论，也不能为了通过删除负面观察。

### 可选模型阶段：无key就跳过，不阻断真人路径

模型审查是可选增强，不是所有影片的前置依赖。无API key时模型阶段记录`SKIPPED_NOT_CONFIGURED`，不调用、不付费，也不算失败或已经听过；可以由真人实际听审和常速声画审查完成相应门。仍缺实际审查的门保留待审，不由skip自动补齐。

固定配置位置为**项目根目录`.env`**；按不含密钥的`.env.example`与工具配置说明，在本地填写，不把密钥发到聊天、截图或报告。`.env`必须由Git忽略，并从可移植包、报告与交付清单排除；提交前运行源码/包检查确认没有凭据进入版本控制。不要把真实key复制回`.env.example`。存在key只代表已配置，不代表同意上传影片或批准预算。源码模式的项目根是仓库根，便携模式是Skill根；工具不搜索其他目录的密钥。

`.env`是长期私有配置，不是临时素材，不得被项目清理或缓存清理一并删除；不进入Git和归档仍是硬边界。环境重置或迁移后可能需要用户在固定位置重新配置；Git恢复、源码包和作品备份不保证恢复密钥，缺配置时给出本地配置指导而非反复猜测。

仓库入口为`python3 scripts/audiovisual_review.py --help`；便携包入口为`python3 runtime/review-tools/audiovisual_review.py --help`（在Skill根运行）。该工具提供完整音频＋**明确稀疏帧**的模型辅助观察，不是连续视频或完整AV通过门。

本地准备示例（不会联网）：

```sh
python3 scripts/audiovisual_review.py prepare /local/complete.mp4 \
  --expected-sha256 ACTUAL_MOVIE_SHA256 --output /local/review/model-input
```

实际`call`必须遵循该版本`--help`与配置说明，单独确认上传范围、当前价格及预算；没有授权不执行。只在真正调用后保存原始回执，不能把prepare或配置完成写成模型已审查。原型的片长/轨道/输入上限由工具校验，超过能力不能裁去未审段后假称全长覆盖。模型回执需按上节核证，不直接转成视觉或声画`passed`。

## D. 声画：常速完整观看＋高精度事件复核

先完整常速合看，再用事件表定位关键声音与视觉关系。每行至少记：

`事件ID | 视觉对象/动作 | 视觉起止PTS或区间 | 音频事件起止或区间 | 事件语义/职责 | 对应依据 | 提前/滞后范围 | 不确定性 | 常速感知结论`

- [ ] 视觉时间用原生高分辨率事件帧核定，明确“开始预备”“实际接触”“后果出现”等所选语义；不能把不同语义的两个起点相减。
- [ ] 音频时间以最终编码的解码时间轴定位；听感确认后用波形/onset辅助标区间。考虑编码延迟、容器起点、片段偏移和重采样映射，不能假设都从0开始。
- [ ] 时间只知区间时保留区间，例如视觉`[v0,v1]`、声音`[a0,a1]`，则相对延迟范围为`[a0-v1,a1-v0]`；不将区间中点伪装精确同步。
- [ ] 稀疏抽帧间隔就是视觉时间不确定性的下限之一。单个抽帧“看起来对应”不能排除帧间先后错误；补原生密集帧和正常速声画观看。
- [ ] 意图性提前、拖尾与有意静默按脚本职责和实际感知评估；不设置通吃所有事件的“零延迟=好”标准。
- [ ] `normal_speed_av`要求真实完整常速合看。高精度事件表是补充证据，稀疏模型AV或离线指标不是该方法。未来若支持其他等价完整感知方法，需显式新增合同与测试，不能把现有输入谎标成该方法。

仅有真实音频回执和静帧时，可输出有价值的事件疑点与待审报告，但AV门仍未完成。

## E. 模型意见裁决、问题关闭与版本失效

每项观察先归类为：**阻断目标**（信息/因果错误、缺少必须审查）、**需修缺陷**（明确的可读/听感/同步问题）、**可接受取舍**或**方法不确定性**。这些用于安排工作，不是总分或自动艺术排名。

1. 核身份：意见针对当前媒体hash和实际输入范围吗？不是则标旧版/不适用，不据此返工当前片。
2. 核事实：以同PTS原生帧、邻帧、原声与常速观看重查；分别记录支持与反证。真实provider回执只证明该调用/响应存在，不证明判断正确。
3. 核影响：对照brief、参考保留项和观众实际目标，决定修什么；不用“模型说好”替代用户否决。
4. 记录`issues`：每项`finding/disposition/rationale`。未结问题保持`pending`；`resolved`写修复与复验证据；`accepted`写接受者、范围和具体取舍理由。不能接受掉缺失的必须审查，不能擅改用户要求。
5. 改片后重算hash，旧版全部感知记录不能直接绑定新版；局部修复可聚焦重查受影响窗口及邻接状态，但新版完整常速视觉/听觉/声画覆盖仍须真实完成，或明确剩余未验。技术检查和最终报告重跑。
6. `limitations`用于方法/范围局限，不用于藏未修问题。未验、失败、用户否决各保留原义。

## F. 交付前最后一遍

- [ ] 三类记录方法真实，覆盖完整，观察带时间，`issues`无未关闭阻断；未签名明确`declared_not_authenticated`，可选签名不证明感知事实。
- [ ] 成片、原始记录、画面/会话证据hash匹配；没有拿参考片、旧版或技术夹具当当前作品。
- [ ] 运行[完整交付门](delivery-workflow.md#6-完整交付门不能用时长绿灯代替视听审查)，依[证据合同](final-delivery-evidence.md)生成报告。
- [ ] 打开HTML核图片、阅读顺序、时间窗、未验原因和状态；交付结果清单绑定报告hash。
- [ ] `ready_for_owner_review`只表示本流程证据门具备，非艺术认可、非OWNER已接受。缺失或阻断则明确交付`review_candidate`，不宣称批准最终版。
