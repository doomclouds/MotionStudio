# 五核心视频导演（整合候选，未验证成熟）

先分两条轴：工作方式是原创/授权复刻/修复，传播主任务是发布展示/工作流演示/解释教学/角色故事/品牌或情绪表达。混合片写明主任务；用户已定片型和主张优先，不能用惯用人物剧情覆盖。先用一行brief写“给谁看｜要让其知道或相信什么｜必要主张与证据｜时长/画幅｜已定方向与待定事项”，再决定故事是否必要。发布片先解决新品身份、关键能力或成果证据、可用性，不强制单任务、角色或戏剧弧。信息可合理推定就主动推进；只询问真正缺失的事实、权限或重大方向，不把用户当持续质检员。

主栈为 Node.js + @napi-rs/canvas 原生 Canvas 逐帧绘制 → PNG → FFmpeg。生产核心不调用浏览器、CDP、GSAP、上游 Skill 或远端服务；核心源码唯一维护于仓库 `engine/motion-render-core/`，从本 Skill 通过 `runtime-source.json` 定位；可移植包使用构建生成的 `runtime/motion-render-core/` 快照。音频编辑/混音由 sibling `motion-timeline-core` 与 `motion-audio-core` 负责，可移植包同时带三核心与 `motion-elements` 基础元素包；音频时间线入口为 `--audio-timeline`，完整视频 NLE/视频 clip adapter 仍未实现。实际入口见[引擎使用](references/engine-use.md)，接口见[渲染合同](references/render-contract.md)，已验范围见[环境](ENVIRONMENT.md)，来源见[许可](NOTICE.md)。原生小样通过不代表完整影片、跨平台或艺术验收通过。

**证据与任务锁**：以当前委托的明确要求和可用证据为准；技术夹具不计作品。公开工具集不附私人影片、个案反馈或历史研究数据；适用范围见仓库 SOURCE-SCOPE.md。

## UI 设计条件交接

只有当前影片存在明确 UI 内容结构、视觉层级、状态或关键画面缺口时，才委托 UI 设计流程；已有认可设计或局部可直接修复时不强制另起设计、多方案或重新打样。仓库内按 `AGENTS.md` 读取 `skills/ui-design-director/SKILL.md`；这是人工/代理可读流程，不是自动调用 API。委托携带原 brief、事实与权限、画幅/镜头/读时约束、锁定方向、现有代码和具体缺口；接收其 DesignHandoff 后核对象/状态映射、版本/hash、依赖及未验项，填写 motion_receipt 并记录采用/偏离与复验范围。UI 不反向启动 Motion；Motion 保留叙事、时序、运动、声音和全片验收责任，静态认可不代替成片门。 已有校样或待审字段差异的解释片，再按[待审比较运动方法](references/editorial-comparison-motion.md)核完整值读时、单项注意力、业务状态、共享 cue 与实际依赖；方法候选不升级验收。

独立安装本 Motion portable 包时，UI Skill 与 portfolio 不随包提供；公共设计知识以同源 `knowledge/design/` 快照随包提供，但这不等于 UI Skill 或完整作品库；先核可达性，不执行不存在的路径。缺少 UI Skill 时在当前已授权任务内继续现有美术流程，明确所缺设计证据，不虚称发生过委托。直接 UI 任务无需绕经 Motion 或制作视频。

## 声音条件交接

需要声音方向选择、旁白/配音表演或新版声音退步修订时，执行 [声音导演工作流](references/sound-direction.md)。仓库可从 `skills/sound-director/SKILL.md` 独立进入；便携包直接读本工作流，不依赖包外 Skill。已有认可声音保留其范围，不强迫换曲或加旁白；Motion 保留最终时序和成片验收，技术指标不代替实际听审。

只审核已有视频/音轨，或单独制作配乐时，完整仓库另有 `skills/video-review/SKILL.md`、`skills/audio-review/SKILL.md`、`skills/soundtrack-production/SKILL.md` 三个薄入口；直接完成对应任务，不先重开制片流程。它们复用本包的审查/声音正文和现有工具，不新增自动调度、模型作曲或通过门。默认单 Motion portable 不含这三个入口；源码构建器 `--media-skills` 可将它们与本 Skill 并列打包，见仓库 `skills/MEDIA-SKILLS.md` 或组合包根 `MEDIA-SKILLS.md`。便携模式继续共享本页正文与工具，不复制多份 runtime。

## 参考研究边界

原创或重大重设计在定方向与编码前执行共享[参考发现→蒸馏→有意图组合](../../knowledge/design/reference-to-composition.md)：主动寻找/筛选优秀成品，实看跨例对照，提炼适用原则与反例，再以主张驱动 UI、运动、声音的职责、组合及原创变形。本阶段按共享页的需求拆解→查积木及参考对象→融合创作→实作发现缺口→缺口驱动复刻学习/补充→验证再创作循环学习，不要求每次小修都扩库。按共享流程先建立整页/关键画面的整体视觉锚，再落实积木，使品牌、色彩、比例、密度与核心主物及外围系统协同；ImageGen 可探索整体概念或生成素材，但须区分概念、素材、代码与已验证交互，不用生成图冒充用户要求的代码。真实调用/执行与来源启发分开，按实际输出对照质量，不以积木数量或技术通过背书。已有方向小修只复核受影响关系；缺参考/未实看的处置与跨目录检索按该页执行，不虚称研究完成。

需求拆解后先读[创作参考图书馆](../../knowledge/design/library/INDEX.md)总索引→相关分类索引→原始契约/例子/反例，由模型比较分析并选择UI、运动、声音与作品参考；不要求运行检索工具。UI 设计的方法与边界仍读[共享知识索引](../../knowledge/design/INDEX.md)，再按[MotionStudio 制作路径](references/design-to-motion.md)连接美术、导演与现有积木；静态案例不自动成为运动/视频能力。

固定画幅 UI 研究先读[静态 UI 复刻合同](../../knowledge/design/static-ui-reference-study.md)：锁定来源/画幅/状态，分离 token 来源与测量，保留实际输出与修订证据；静态、交互、响应式、视频/音频、作品接受与发布授权各门独立。

研究参考时记录观察方法、授权范围、可迁移关系、反例与未验项；实际媒体和研究记录保存在用户自己的私有工作目录。公开版不含历史案例库或素材目录，也不声称那些案例已获公开许可。通用[知识工作流](research/video-knowledge/WORKFLOW.md)、[卡片契约](research/video-knowledge/SCHEMA.md)与检索/校验 CLI 只读取统一schema 3的用户自备外置私有库；默认库为空。Case必须明确decision记录状态；无记录用not-recorded及原因，不编造决策，未执行计划不得冒充结果；旧库须显式[一次性迁移](research/video-knowledge/MIGRATION.md)，无运行时兼容。

合成静态/代码探针使用同一schema 3的显式 [static-probe类型契约](research/video-knowledge/STATIC-SCHEMA.md)，不伪装成带时长的视频或生产迁移。复用静态记录前必须先对明确授权的本地素材根运行 `video_knowledge.py --root <库> verify-artifacts --artifact-root <授权根>`；missing/mismatch/blocked/stale 均禁止据此复用，须复核或新 run。`decide` 不自动读取此报告，也不证明文件仍新鲜；即使 hash 全部匹配，也只证明字节身份，不证明执行、观看、听审或艺术/生产验收。

用户指定参考的外观或形式时，先按[指定参考保留合同](references/reference-mechanism.md)锁定媒介、像素/角色场景样式、视角、玩法形式与叙事机制中的必留项，再做抽象迁移；自驱不能擅改已定风格。形式或故事被否决先停对应制作，两者都被否决不能只换皮续用旧故事。

代码美术不足或要把生成场景做成可控动作时，按[混合美术生产](references/hybrid-art-workflow.md)选择代码/imagegen/真3D分工，并用其brief、分层manifest与检查单；不把整图平移当完整动画，也不默认全片生成化。

分层光效遮挡、跨镜头尾迹或已认可片段接入全片时，读[分层与接续合同](references/layered-continuity-lessons.md)：分别核 alpha/遮挡、位置/速度/历史、整数帧映射与原生 hash、音视频时间基准；工程回归不替代连续视听或艺术接受。

涉及像素角色、极简块状吉祥物或角色动作时，先阅读[角色表演](references/character-performance.md)；先验证无文字与特效的姿态、接触和节奏，再选择 rig、逐姿态重绘或混合实现。

## 选题能力与负反馈边界

优先研究与制作明确由代码生成的 UI、字体、图形与快节奏编排；不要只因参考好看就选题。主要依赖细腻光影、材质质感或摄影运镜的作品，目前超出已验证的驾驭能力，不作为自驱默认方向；先验证主导难点，不能以微弱平移、光点漂移或静态分层冒充原作的运动质量。这是当前能力/选材风险，不是永久禁止某类技术；用户明确指定时据实说明差距。

完整作品被用户否决，私有 Case 必须记为作品质量不通过，而非继续以技术 passed、局部曾认可或“仅待听审”充当成功案例。实验示例及失败版本不可作默认推荐或风格锚点；单个机制的艺术未验、生产迁移未验与已有技术证据分别保留，不将整片否决推成每个原语数学错误。

## 可复用动效入口

编码新的基本动作、转场、错位构图或组合效果前，先读[动效基础库](references/motion-elements.md)，再查 `motion-elements` 的静态目录。优先复用、组合或新增配方；只有独立机制缺失时才扩底层。不把参数变体计成新动作，不从目录动态执行外部代码。新效果先做合成最小例并检跳时、边界、状态恢复与常速观看，再关联私有 Case/Technique；技术通过不自动升级为艺术通过，公开默认知识库仍为空。

## 最短闭环

brief/主张→参考发现筛选与实看跨例蒸馏（小修按影响缩减）→意图驱动的积木组合/原创变形与对照判据→实质方向选择→视听脚本→低成本全长animatic＋关键风险短样→实际制作→独评/回归→交付与反馈。执行[样片到完整交付](references/delivery-workflow.md)：用户可见样片至少7秒（不是恰好7秒），默认只交付带可听声音的视频，由用户判断方向与感觉；内部技术/画面QA照常据实执行，不默认向用户附PNG/HTML报告或资源包；内部短测试不是样片交付；样片通过后直接进入完整时长production，不逐次改长度重复申请用户审核，不让组件/Skill沉淀阻塞交片。已有通过样片不为新流程重跑。用户要求多个方向时，按其数量给出信息排序、证据组织和视觉机制不同的方向卡及取舍，不只是换道具；已有明确选择就沿该方向推进，重大改变才重新确认。局部修复按影响范围回归，不机械重建整片预演。

|平面美术|主体/层级/字形/材料怎样服务当前阅读与动作|[美术](references/art.md)|

本工作版的首要缺口不是“补完听审就成熟”，而是独立选择目标、材料和方案的能力。复刻/工程成功不能证明原创规划成立；技术过程正确也不能抵消角色与软件表现失真。见[脚本取舍](references/script.md)与[材料选择](references/art.md)。

## 检测只做辅助工作

按共享[检测工具的辅助职责](../../knowledge/design/reference-to-composition.md#检测工具的辅助职责)先定问题、可比条件、覆盖与反证。小差异不反推高吻合或好看；信号/声明检查与真实内容观察分列。实际入口与外置项目路线见[有引导的自审](references/guided-self-review.md#仓库外私有项目的当前路线)。单片 motion-check 找复看窗，双片 benchmark 对照信号，事件工具比较已观察注释，均不代替完整动作、正常速观看与实际听审。短片显式选片长内的窗口/关键帧并核实际产物，缺省事件或被跳过的窗口保持未覆盖。

## 每轮怎样指挥与收口

沿共享流程的[逐轮指挥与反馈回流](../../knowledge/design/reference-to-composition.md#逐轮指挥与反馈回流)，把每轮改动指到当前版本的镜头/时间窗、观众应看到的变化、必须保留的形式与对象、UI/运动/声音各自职责及复验方法。实现者返回真实调用、输出身份、观察与未验项；导演据此选择保留、撤回或继续修复，不按效果数量或解释文案裁决。单人执行同样留痕，不要求额外代理。

先分清方向错误、表达/因果不成立、执行缺陷和审查缺口：前两类回到主张/参考关系，执行问题做最小修复，缺连续观看或实际听审则补对应证据而非继续堆效果。用户认可的片段保留其明确范围；接入全长后仍查上下文、接续、读时与混音。用户明确否决的整片停止作为成功锚，局部可用机制只保留原有有限证据。反馈及经验进入现有私有 Case，公开只回写改变下一次选择的去素材化方法；不为沉淀延误当前交片。

收到重点不清、拖慢或衔接生硬的反馈时，先用[重点交接与节奏判断](references/motion.md#重点交接与节奏判断)区分主次、因果推进、重复密度与快慢对比，再选连续桥接或有意硬切；不把全程运动、取消全部切镜或统一加速当成修复结论。

## 有引导的自审入口

实际执行按[视听审查操作规程](references/audiovisual-review-sop.md)：冻结当前hash和时间坐标→全长视觉/实际听审/常速声画分门观察→同PTS与音频事件核证→裁决模型意见→关闭问题并复验→交付可视化报告。方法可用不等于本片做过，provider回执不等于判断正确。

交付前先读[有引导的自审](references/guided-self-review.md)：从 brief/参考/主张/音频选择方法，仓库根 `python3 scripts/review_film.py plan <成片> --source-root <项目目录> --brief <目标与反证>` 生成逐方法引导；`run` 仅运行本地技术层或复用同 hash 证据，`report` 重核失效。参考复刻用同页 `compare` 显式配对真实PTS/帧，声明文案/字体替换与录屏缺陷；采集不代表匹配成功。分层图像动画另核资产hash/alpha/注册、烘焙与独立运动边界及主动因果；局部用户认可只冻结明确对象，不外推为整个前段获准。技术、视觉、原生音频、OWNER艺术接受四门分列；未跑/阻断/缺失/过期不能算通过。人工常速播放与实际合听不自动代填，原生音频只走单独授权入口，不默认调用或付费。方法能力和“本片实际做过”分开，详见[方法注册表](references/review-methods.json)。 整体方向已认可、只做快节奏感官发布片精修时，按同页“感官发布片的局部回归”保护结构、定位缺陷并复验，不以增加效果数量冒充进步。

**参考复刻、用户要求视听基准/差异比较、或用户指出新版退步时**，先按同页“同格式视听基准与内容门”锁定原片/旧版与候选，使用[本地视听基准导出](https://github.com/doomclouds/MotionStudio/blob/dev/tools/reference-benchmark/README.md)生成同 schema、同配置、原始时间对照；缺失或受阻明确保留，不以统计相近替代材料/动作/叙事判断。需要确认声音选择、掩蔽、声画因果或内容可读性时，必须补对应范围的真实内容观看/实际听审；未执行不准过相关门。内容标注另有[独立离线证据校验与 HTML/JSON 导出](https://github.com/doomclouds/MotionStudio/blob/dev/tools/reference-benchmark/CONTENT_REVIEW.md)，只验记录与媒体绑定，不自动理解或评判成片；不能把 schema 有效或计划写成已评审。

## 不可遗漏的核心门

- **全局镜头**：冲击/震动/推拉至少跟踪两个独立固定世界锚的逐帧共同位移与尺度；区分主体形变、世界相机和屏幕UI。不能只测主体bbox或切点。回归附属物、近远景和未拟合时间。
- **动作/交互存在时的完整因果**：预备→接触→受力/操作→实际后果→释放→恢复。核姿态、支撑脚、相对速度，UI预览与操作来自同一状态；不让结果早于起因，不靠删除对象假装完成。
- **镜头可读**：在目标观看尺寸检查手、对象、文字读时与结果。必要时近景，阅读时稳镜；不强迫全程zoom或全程运动。
- **声音覆盖**：关键事件逐项有声音职责或有意静默；存在音轨、峰值安全、模型标签均不等于听清。BGM掩蔽按事件核实，编码后复测与实际合听；未听就写未验。
- **独立与反证**：先给评审需求和输出，后给解释。疑似条纹/栏杆/错位先核原生帧与邻帧，评审也会错。技术绿灯不能抵消用户否决；用户认可不替代许可/跨平台验证。
- **原子输出与恢复**：临时文件编码完成→帧数/全量解码→同目录原子改名。绑定源码/成片hash；独立目录恢复合法资源、字体、锁定依赖并检代表输出。同机恢复不冒称新平台通过。

每项标明证据方法：文本、静帧、密集帧、连续无声视频、实际合听、程序测量、用户反馈。密集抽帧不是连续观看，模型分析不是人耳试听。输出必须绑定版本，修改使相关旧证据失效。

交付前读[权利与范围](RIGHTS.md)，最终检验与未验项据实列出。 **有声完整交付须同时有视觉、实际感知听审（真人或真正接收声音的模型）、声画同步、技术检查及绑定同版成片的可视化报告**；执行[完整交付门](references/delivery-workflow.md#6-完整交付门不能用时长绿灯代替视听审查)。`NOT_LISTENED`、指标分析或手填布尔值不能充当实际听审；有实质证据的未签名记录可满足声明式审查，须标记`declared_not_authenticated`，签名仅为可选来源认证；受阻只能明确交付待审候选，不冒称批准最终版。

需要看具体差别时，在项目本地 `output/` 或 `verification/` 生成接触释放、撤销中景、结果留读与声音职责的对照；不将截图或离线评审页面提交进源码仓库，也不把静帧当连续运动。

需要定位复看时间窗或核编码时，按需用[轻量技术工具](references/technical-checks.md)：逐帧计数、完整decode、接触表、4Hz帧差热图和EBU音频测量。**4Hz会漏短震动/单帧故障；不替代双锚跟踪、正常速视听或审美判断。**

明确要求系列打磨时，按需读[逐支局部创新与计时](references/iteration.md)：先预算预检，再单支验收，不把计划/旧片计新作品。

研究优秀作品时先核整片承诺与信息/证据结构，再用[机制研究卡](references/reference-mechanism.md)研究关键局部。不把逆向拆解称原稿，不把参考数量或技术短样当完整片通过。

完整成片交付固定PNG总览＋HTML报告，并附简短经验沉淀总结；样片不要求报告。成片报告遵循版本化[交付报告规范](references/audiovisual-report-standard.md)，结构有效不等于影片通过；复用[审核校准经验](references/review-calibration-lessons.md)时保留适用边界，不把候选配方当已实现能力。

需交付可编辑源码、接续制作或可迁移工程时，执行 [三导演可重建交接](references/rebuild-handoff.md)：给接收方完整命令、输入/版本校验、明确根绑定与例外，实际在新项目根重跑后才报告已测恢复范围；普通成片交付不强制附工程包。


明确由用户或用户已批准作品合同指定的**无音轨整片**，按[无声适用性合同](references/final-delivery-evidence.md#明确授权的无声整片声音适用性不是听审豁免)提交同版授权声明；声音/声画同步记不适用，不伪造听审或空音轨。未提供明确授权、有音轨（包括静音音轨）或仅听审受阻时，原有有声交付门不变。全长视觉、技术和报告要求仍适用。
