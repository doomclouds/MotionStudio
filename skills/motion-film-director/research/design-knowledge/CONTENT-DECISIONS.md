# 不同视频内容如何选择 UI 表达

这是导演的**人工决策指南**，不是内容关键词→模板的自动匹配。两张已有卡仅是静态方法摘要（S：静态经验）；下表视频选择均为 H：待验证迁移假设，不是 V：本片视频实测。目录命中和代码测试不能把 S/H 升为 V。

## 每片先写六项，不先挑好看的皮肤

1. **内容事实**：要讲的主张、证据/数据、必须保持的对象关系是什么？是实际产品演示还是原创解释？没有真实数值，就不能造一个 dashboard 装作证据。
2. **受众与目的**：谁看、已有知识、观看屏幕、希望理解/比较/操作/感受什么？手机短片与桌面培训不能共享未经验证的信息密度。
3. **信息任务**：观众要比较数量、理解因果、追踪状态、记住步骤、辨认空间关系，还是体验情绪？一镜优先解决一个主任务；次任务须有明确读时。
4. **结构/风格/密度**：先选关系结构（并排、序列、网络、模块、单焦点），再定层级/色彩角色/字体/密度；“科技/高级/活泼”不足以决定结构。忠实复刻受源状态约束；原创重排需在 brief 中明确。
5. **运动绑定**：每个动作回答一个信息问题，锁对象身份、前后状态、层序和阅读 hold；颜色、字号、光效不是运动机制。映射到 [MotionStudio 导航](MOTIONSTUDIO.md)后查实际 API 限制。
6. **验证与退出条件**：固定目标设备/画幅/时长，先看静态层级再常速观看。写出“观众应能复述什么”和误读风险；不能读清就减量/拆镜，不默认缩字或加速。听审与艺术接受另列。

## 按信息任务选择，不按行业硬套

| 内容/主任务 | 候选 UI 结构、风格与密度 | 动作承担什么 | 不适用/证据门 |
|---|---|---|---|
| 数据趋势、方案对比：看出差异 | 同口径并排或单图逐层解释；中性容器，色彩只编码有证据的系列/状态；只露出当前论点所需指标 | 先建立共同尺度，再引导焦点；数值与图形同源，不为动效改数据 | 无真实数据、口径冲突、情绪叙事不强加 dashboard；[ui-001](cases/ui-001-dashboard.md)只支持 S，动作是 H |
| 工具/仪器教学：理解控制关系 | 按功能邻接的模块；角色色跨模块一致；一次聚焦一个输入及其可解释结果 | 保持控制对象身份，引导输入→结果；未知映射不画成真实因果 | 无真实交互/DSP 数据只能标示意；[ui-002](cases/ui-002-instrument.md)只支持 S，因果/音频是未验 H |
| 流程/产品讲解：知道下一步和状态变化 | 序列、少量步骤或局部界面；主动作与反馈层级清晰，辅助信息渐进出现 | 状态交接与焦点接力，而非整页同时飞入 | 真实产品不可伪造功能；长页缩成一屏无读时应拆镜；尚无本库对应静态/视频实证，仅 H |
| 复杂系统/概念解释：理解依赖 | 节点/连线或分层模块，显式图例，控制每镜关系数量；不因“科技感”增加装饰指标 | 依次揭示因果/依赖并保留已建立关系 | 连线不等于因果；无依据不生成因果箭头；仅 H，先核语义再选几何 |
| 情绪、人物、品牌故事：形成感受或记忆 | 可能不需要 UI；主体/影像/少量文字优先，界面只在故事需要时出现 | 服务主体、停顿和节奏，不强行套卡片或仪表盘 | 无信息任务就不选 UI 方案；写实光影/材质/复杂运镜不能假定当前引擎能做好；仅 H |

## 冲突与未知时如何决定

- 受众、主张、数据来源、屏幕/画幅或授权任一关键项未知：列出缺项，先核必要事实；可画低成本结构草案，但不能称推荐已验证或擅自编数据。
- 忠实复刻与手机可读性冲突：明确报告冲突。保留原画幅分镜/局部查看，或另立原创适配 brief；不能暗中重排后仍称精确复刻。
- 信息过多与时长冲突：优先压减次要内容、分镜、延长读时；这些会改变委托范围时先取得决定，不靠极小字号完成形式交付。
- 多个方案都合理：列出各自要解决的任务和代价，用同内容/同画幅/同预算小样比较；不把主观偏好包装成统计优胜或模型能力提升。
- 目录无匹配/反例命中：允许“不推荐现有卡”。回到内容关系设计，记录 H；不为了复用强行改影片内容。

## 项目决策记录（留私有工作区）

`内容主张 → 受众/目的 → 主信息任务 → 候选与淘汰理由 → UI结构/色彩角色/密度 → 动作与读时 → 实际catalog ID及限制 → 证据等级S/H/V → 待测项/失败条件 → 本版复核结果`

两例提供的是设计观察与检查方法，不证明某种 UI 在任何视频里有效。只有当前明确版本实际制作、常速观看并核对理解目标后，才可为相应范围记 V；技术、听审、用户艺术接受和发布许可仍不得合并。
