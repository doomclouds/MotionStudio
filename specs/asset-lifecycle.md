# 资产生命周期

PROPOSED：以下为人工治理流程，不新增 JSON schema 或自动晋级服务。

## 先分类、再保留

资产分别记录：身份/版本、来源和适用许可、用途/授权范围、所属项目或模块、维护者、依赖与恢复方法、验证边界、替代/退役关系。具体字段复用作品 work/1、Case/Technique、catalog 等各自契约，不能把本表直接塞进未知 schema。

| 状态 | 可做什么 | 下一步的必要条件 |
|---|---|---|
| 外来参考 / 未核验 | 在授权范围内研究，记录未验 | 核来源、权限和实际观察，不能直接公开 |
| 私有实验 / 候选 | 独立目录试做、失败也保留反证 | 输入和版本可追溯，实际结果与计划分离 |
| 可复用方法候选 | 写适用、反例、限制和复用假设 | 不同内容验证及反证，独立审阅；不能凭数量自动晋级 |
| 审定公共方法/代码 | 按既有域契约登记 | 发布范围审查、合法来源/署名、相关测试、索引同步 |
| 审定作品源码投影 | 按 portfolio 准入保留 | 完成、明确收录、公开权利范围、实际源码恢复；详细规则仍以 portfolio 为准 |
| 过期 / 撤回 / 替代 | 保留必要追溯，停止默认推荐 | 标注原因与替代；修复依赖并重新复验才恢复 |

这些是治理标签，不覆盖现有 schema 的枚举。作品收录与方法晋级相互独立：漂亮作品不自动证明通用机制；技术例不自动成为作品。合成测试、真实制作迁移、用户接受分别判断。被否决整片不能再作为成功案例默认推荐，局部技术事实也不因此被篡改。

## 素材与源码边界

字体、音乐、图标、原图、品牌和参考媒体分别核许可；根 MIT 不覆盖第三方条款。外置资源按项目已定义的来源/hash/恢复方法准备，未知授权就不分发。输出、帧序列、报告和依赖默认仓库外；公开封面/文档预览仅沿用已审定例外和现有 allowlist，新增例外需单独明确审查，不批量放开扩展名。

## 失效和退出

内容、代码、字体、依赖、渲染参数或媒体变化时，受影响的身份绑定/证据失效；只保留不受影响的证据并写范围。记录旧版本与新版本关联，不覆盖旧输出。清理只先列待删对象、依赖和恢复能力；没有明确删除授权，不删除私人备份、原始项目或 Git 历史。撤下活动索引不等于清除历史泄露，历史处理另审。
