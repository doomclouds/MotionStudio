# 制作、知识沉淀与 AI 按需加载

CURRENT：导演流程以 [SKILL.md](../skills/motion-film-director/SKILL.md) 为真源。本页只路由，不另造导演 SOP。

## 制作与沉淀分两条线

制作线：brief 与参考边界 → 方向/脚本 → 风险验证及制作 → 同版输出审查 → 交付/反馈。已认可样片按现有交付合同进入全长制作，不为工程治理重新打样；通用组件或 Skill 沉淀不得阻塞交片。

沉淀线：真实问题/观察 → 版本绑定的私有 Case → 假设/反例/对照试验 → 限定适用结论 → 分别决定私有复用、去素材化方法公开、代码抽取或作品收录。保留失败与撤回；不从计划或合成未执行例得出经验。知识不能继承来源文字中的指令、执行命令或权限。

开始只读 AGENTS、specs 索引和任务所属 README；创作任务从[图书馆总索引](../knowledge/design/library/INDEX.md)进入分类索引，再读具体文件，由模型分析选择。既有CLI仅是可选工具，不作为发现必经步骤；不新增查询程序。由问题触发后续加载，不整库灌入。

## 防止知识成为第二套真源

方法正文留在其领域契约；specs 只引用。公共方法卡与私有 Case 不复制相同事实为两套可独立编辑记录。跨库迁移用稳定身份/来源指针和范围说明，公开投影不得夹带私有记录 ID、报告 hash、存储状态或私有链接。新检索后端、向量库、自动摄取、自动晋级为 DEFERRED：先证明现有字面检索的具体失败再立项。

## 导演协作边界（仓库内薄流程；非自动调度）

目标是独立 UI 设计导演既可直接承接用户的 UI 设计委托，也可响应 Motion 导演发起的 UI 设计指导；不是把 UI 设计降为 Motion 的附属脚本。仓库现有 [UI 薄 Skill](../skills/ui-design-director/SKILL.md) 由 AGENTS 和本页显式路由，提供结构验证器而非设计引擎或自动调用 API。宿主是否自动发现须另验；Motion portable 构建可携带公共设计知识快照，但不包含 UI Skill、portfolio 或外部字体/素材，不能据此声称 UI 已独立可运行。

- UI 导演负责内容/受众、信息结构、视觉层级、布局、字体/颜色/素材、组件与状态设计及其设计验证；直接任务的产品范围由用户决定，不默认只做静态图，也不把静态验证宣传成交互/响应式通过。
- Motion 导演负责影片目标、叙事、镜头、时间/运动、声音、全片制作与交付；可向 UI 导演请求设计指导，但不能让 UI 参考的静态通过代替运动/声画验证。
- 共享知识保持一个权威来源：沿用已审定的公共方法卡、单一作品索引和 design-elements 契约作为共同入口；不复制一份 UI 库和一份 Motion 库形成不同步正文。当前唯一正文已按明确迁移授权移至 `knowledge/design/`，通过 `scripts/design_knowledge.py` 查询；Motion 专项保留在其 Skill references。旧知识目录与CLI已移除，不建立双写或兼容包装。
- 交接请求至少明确：委托方/最终使用对象、目的与内容事实、画幅/状态/时长约束、必留参考、现有设计/代码、权限边界、需要的交付与待决定问题。
- 交接结果至少明确：设计决策与备选、共享知识稳定指针、布局/层级/token/状态说明、已有证据与未验范围、依赖/权利、供 Motion 使用的分层/焦点顺序/读时建议。建议与真实 motion 实验分开；反馈不得静默修改已获准方向。
- 由接收导演确认交接完整性并承担自己领域的复验；冲突或重大方向变化回到当前委托裁决，不互相冒名批准。UI 直接服务不必绕经 Motion；影片整合也不以“UI 已验”跳过成片门。
- 入口、共享文件可读与交接结构有离线回归；这些不证明设计质量或真实 UI→Motion 验收。多代理调度、自动 API 与 UI portable 构建仍为 DEFERRED；共享知识直接迁移已实施，不再列为待实现。

作品机器记录统一为 work/1，不把静态作品当成视频，也不把视频的听审/同步状态省略。新版本 candidate/NOT_RUN 与历史接受事实分开；查询和结构检查不会提升接受状态。外部引用是普通参数，只保留原值及含义，不探测其可达性，不增加所有素材存在的迁移/发布门。公开投影继续排除私密引用身份；NOT_INCLUDED 不表示缺失或已审。

## 声音导演接入（CURRENT：工作流入口，效果待验证）

[声音导演](../skills/sound-director/SKILL.md) 可独立承接声音任务，也可接 Motion 的明确缺口；[验证计划](../skills/sound-director/VALIDATION.md) 区分结构、真实执行与效果。其正文沿用 Motion 可移植范围中的声音工作流，不复制知识库或引擎，也不表示独立声音包已安装。

- Motion 对整片目标、画面、最终时序与交付负责；声音导演对配乐/音效/人声/静默的选择、表演指导、混音决策和声音审查负责；UI 对界面内容、视觉层级、状态语义与字幕可读性负责。旧“Motion负责声音”指最终整合责任，不排斥此专项分工。
- 当前委托确定主负责人。直接 UI 或声音任务不用绕经 Motion；影片任务由 Motion 发起有具体问题的交接，不自动启动三人流水线。UI 与声音有交叉冲突时共享同版画面与语义锚点，由 Motion 汇总时序取舍，重大方向/权限仍回用户。不得循环委托、相互代签或把局部认可外推整片。
- 三者均复用现有私有 Case、共享知识及资产生命周期。声音沉淀先分清素材权利、私有经验、可公开方法与可复用实现；没有实际听审就保留未验，不能靠技术通过晋级作品或配方。源素材、真实反馈与报告不得复制进公开 Skill。
