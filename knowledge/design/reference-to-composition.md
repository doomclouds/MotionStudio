# 从优秀参考到有意图的组合

UI、Motion 与声音导演共用的原创决策流程；不是自动选风格/评分器，也不声称此流程已证明作品质量提升。原创、新方向或重大重设计在定方案与编码前执行；既有方向内小修只复核受影响关系，沿用仍有效的参考/证据，不重做研究、不强迫另起多案。指定复刻先守其保留合同，不借“原创变形”改掉用户锁定项。

## 本阶段创造目标：需求驱动的迭代循环

本阶段以创造新作品/产品检验积木，而不是先扩库再找内容：`拆解作品需求与问题 → 在积木及其来源作品中找可参考对象 → 提炼关系并融合成新创意产品 → 真实制作发现缺口 → 缺口驱动补充积木/寻找优秀作品复刻学习 → 验证后再次创作`。这是当前阶段的学习目标；通用 Skill 不要求每次小修都跑完整循环，也不把补库或复刻变成按时交付的前置配额。

- 需求先拆成内容/用户任务、表达与体验目标、约束和可验证问题，再依下表找已有族、机制、配方及其来源作品。发现可参考对象后仍须实看、筛选和跨例提炼，不把积木目录当审美标准；没有组合必要时保留更简单方案。
- 先用现有能力实现有意图的融合，以真实输出暴露缺口。区分“未找到”“不会正确组合”“实现缺陷”“确实缺机制”“缺表达经验/优秀参考”，记录触发问题、已有替代与失败证据，不从一次不好看直接推导必须新增积木。
- 真缺独立机制时按所属模块契约补充；已有能力足够则改组合/参数/实现，不重复造族。缺表达经验时带着具体缺口寻找优秀成品，按授权范围复刻关键关系并做对照，再提炼适用原则/反例，回到原需求重新融合；不做无目的临摹或把整件参考换皮冒充新创意。
- 验证分两层：新增/修订积木核 API、边界和独立例；接回作品核表达、视觉、时间与实际声音贡献及用户反馈。机制技术通过不替代作品接受，复刻相似不替代原创成立。仅在有真实证据及相应授权时沉淀通用能力；未完成项记入项目待办，不把本轮候选写成成熟能力。

## 1. 带问题发现、筛选，而非收集好看图片

从 brief 写出本次需要解决的表达缺口：观众应理解/感受什么，现有方案为什么不足，参考需要证明哪种关系。先按需读[内容决策](CONTENT-DECISIONS.md)与[设计指南](DESIGN-GUIDE.md)相关段落，再找实际成品；方法、作品、代码目录不是同一个库。

尚未定位领域时读[创作参考图书馆总索引](library/INDEX.md)，按需求进入静态表达、配方/候选、运动、声音或作品方法书架；已从书架找到候选时直接读其正文，不重复回到总索引。分类索引只带路，继续读原始契约、例子、适用和反例，由模型比较、分析并选择。无需新增或运行检索程序；不把关键词命中、目录分类或收录状态当推荐分。

没有找到时，不直接宣称没有能力或开工套模板：沿邻近分类、完整作品的设计说明/来源关系与真实调用、族或机制guidance继续定位。区分术语差异、导航遗漏、组合不会用和确实缺机制；只展开解决本次问题的资料，记录已读范围与尚缺对象，不全库灌入、不无穷搜索。已有库不足时，在授权范围主动寻找原作者/可靠来源的成品；搜索摘要或缩略图只是线索，不能评为优秀。访问受限、缺素材或缺权利时保留缺口，换合法可观测来源；若仍不足，明确哪些决定仅是假设，做受限探索或请求关键输入，不冒称完成参考研究。用户指定且必须保留的参考不可得时，暂停依赖它的判断，其余可继续。

仅有 Motion portable 时，无 portfolio / UI Skill 不执行其命令；共享方法仍可读，积木路径按包内 runtime 定位。仓库外部引用是数据，不为整理或发布新增全量可达性门；这里仅核本次确需观察/使用的对象。

## 2. 实看、跨例对照，提炼可检验原则

按任务挑有实质差异的参考：比较同一问题的不同解法，而非同一模板换色。没有固定数量；覆盖关键取舍与反例即可停止。原创方向应做跨例对照；若只有一件可实际观察，注明对照缺口，保留竞争假设，不能把单例偏好叫通则。不要求每个小修重新找跨例参考。

先实看完整作品的任务、结构与兑现，再定位关键画面/状态/时间窗。静态看目标尺度；运动看正常速连续片段及上下文；声音判断须实际听到声音。记录来源/作者、版本或观察日期、定位与观察方法，区分“观察到”“解释/假说”“未观察”。历史卡片说已看不代表本次已看；截图、源码、标签、波形不能证明节奏、听感、交互或响应式。

把参考并排回答：主信息怎样突出？哪些比例/留白/颜色角色/材料使其成立？运动怎样转交注意、保持身份并兑现结果？声音怎样承担结构/事件/静默？各自哪里失效、换什么内容不成立？不适用的维度略过，不让 UI 任务强制加声音。

提炼 `观察定位 → 可能有效的关系 → 适用条件 → 反例/竞争解释 → 本任务保留与舍弃 → 如何证伪`。选“优秀”须有与目标相关的可定位优点，同时保留缺陷，不凭名气、收录、数量或技术测试背书。详细视觉方法仍以设计指南为准；Motion 的整片→局部、机制假说与指定参考边界读[机制研究](../../skills/motion-film-director/references/reference-mechanism.md)，不复制第二份合同。

## 3. 由主张选择积木，再设计组合

### 先建立整体视觉锚，再落实零件

从实看参考与本次内容提炼整页/关键画面的视觉锚：品牌语气、色彩角色、主要体块比例、字级与信息密度，以及核心主物和外围布局、标识、导航/控件的协同关系；不适用的界面项略过。先判断整体是否有清晰身份与焦点，再把这些关系映射到积木及参数。核心图像可以是视觉重心，但不能把整体质量都归功于它，也不能用一张精美主图掩盖外围系统失配。沿图书馆分类继续读候选的真实契约/例子/反例，选择能服务整体关系的能力，而不是先拼现成控件再补装饰。

ImageGen 可在权限与实际工具能力允许时用于整页/关键画面的概念探索，也可只生成局部素材；它不是必经步骤，不替代真实参考研究，更不能把生成概念当作已完成产品的参考证据。探索后说明哪些整体关系保留、哪些须因真实内容、实现或状态而调整，不把特定方案或配色固化为通用模板。既定方向小修沿用有效视觉锚，不为此重做整页或强制出图。

在现有项目记录中分清 **概念图、生成素材、真实代码实现、已验证交互**，分别指向实际版本与证据：概念图只支持所见视觉关系；素材须说明用途/来源及可编辑或分层边界；代码须有源码与实际运行输出；交互须实际操作验证。截图相似或局部像素相同不证明外围控件由何种代码实现，也不证明交互可用；未定位源码就明确未知。用户要代码时必须交付真实代码及运行边界，不能用整页生成图、贴图页面或视觉 mockup 冒充所需实现；代码中合法使用生成素材仍须如实标明，未实现项不得声称已实现，未验证项须明确标注，不能冒称通过。

先写本片/本页的核心表达，再建立一条可追溯决策链：

`主张/预期感受 → UI、运动、声音各自功能（或不需要） → 候选稳定 ID / 准确 API → 组合关系 → 本次原创变形 → 风险与对照判据`。

选前读实际契约和源码：UI 决定信息承载与层级；motion 决定对象、状态、时间和因果；声音决定结构、事件反馈或有意静默。不要按“每类至少调用几个”凑数。对有竞争力但弃用的候选写具体理由（争焦点、语义不符、读时不足、权利不清、能力未实现等），不是替全库写淘汰表。不适合就不用；缺独立机制才考虑补底层，不让可用积木反过来扭曲内容。

组合不是并排摆满效果：写明谁是主视觉、谁提供证据、谁转移焦点；共享对象/数据/token，明确层序、遮挡、安全区、时序与留读、运动单写入、声音 cue 的起因/峰值/落定及静默。按需查[设计到 Motion](../../skills/motion-film-director/references/design-to-motion.md)与各模块合同，不重写 API。音频核心未实现的动态处理不能因声音指南提及便假称可调用。

原创变形要改变有意义的关系：依据新内容重组构图、信息展开、对象动作或声画呼应，说明相比参考保留的原则、改写的关系、预期收益与可能损失。只换标题/颜色/快慢不是原创充分证据；也不为新奇破坏品牌、事实和用户已定方向。优先验证最可能失败的关系，不要求整片只能一种机制。

### 组合的具体样例，不是模板

下面是把已有原则落实为选择的方法，不是新的必填报告，也不证明迁移后已有效；只采用本任务相关项。

- **让同一身份承担不同功能。** 先选少量能辨认的形状、字排与色彩关系，再检查它们如何进入主视觉、工具状态与最终输出物：哪些关系保持身份，哪些必须随功能改变？例如主图的强调色可以关联选中对象，但不能让所有控件同时抢焦点。判断整页/整片是否仍能读出一个主张；只沿用一组色值、每幕换一套装饰，或只有中心图片有风格，都不足以证明统一。适用于品牌与创作工具，不要求所有数据界面变成海报。
- **用同一对象的变化兑现承诺。** 先写操作前、触发动作、操作后，再让同一对象保持身份，显示变化的真实后果。已有 [Tessel 日程数据](../../portfolio/works/tessel/src/reference-data.mjs)与[状态编排](../../portfolio/works/tessel/src/choreography.mjs)展示了按事件 ID 连接拥挤日程与重排结果的方法；其非官方复刻归属与边界见[作品说明](../../portfolio/works/tessel/README.md)。迁移时核“文字声称的结果是否真的发生”，而非只查卡片有没有移动；静态 UI 可用同状态证据或清晰的前后对照，不必强加动画。源码能说明实现结构，不能替代本次体验验证。
- **保留具体形式中的表达能力。** 从参考提炼故事时，同时检查用户锁定的媒介、玩法、视角和角色行为。像素闯关的作用可能来自跑跳、受阻、反馈和过关的连续后果，而不只是“目标→障碍→结果”三个词；已有 [Favorite52 关卡源码](../../portfolio/works/favorite52/src/legacy/source/v3/game/gates-next.cjs)可用于研究此种状态组织，非官方来源与资源限制见[作品说明](../../portfolio/works/favorite52/README.md)。指定形式内改内容，不能把动作全部换成信息卡后仍称保留了参考。未指定游戏形式的任务也不应机械套关卡；采用与否仍服从本次需求。

## 4. 实现与质量对照闭环

在项目私有记录中区分：来源启发、拟选、真实调用、已执行和已验证。真实复用须指向本版源码 import/调用位置、参数/配方及输出版本；仅挂稳定 ID、抄标签或“适配过”不算实际调用。没用库而自实现就如实说明，不伪造使用账单；代码执行也不证明表达成立。

对本次承担画面、布局或状态职责的既有能力，指出返回值/状态由哪个绘制或后果计算点消费；仅保存而未用于输出的字段不计该职责。若实际使用或依赖关系仍有疑问，只对相关机制做最小同版扰动或删减对照，核实际输出中预期区域/后果是否改变，并核应保持不变的部分；不要只看全图差异。逐帧样本数、额外寻帧检查的总调用数与真正消费输出的区间分别记录；预先计算但未进入画面的字段不计该阶段复用。调用计数、依赖清单、文件身份和像素变化各有边界，不单独证明表达有效；微小幅度与局部未验项照实保留。不要求每个简单调用都新建对照，也不为增加使用量强加机制。

原生制作也要分层记账：`render-shot.mjs` 的帧序列、编码/解码和版本记录证明实际制作入口；`sampleMotion` 的活动矩阵进入物件坐标、`solveTwoLinkIK` 的返回关节进入肢体绘制，才证明相应机制消费。一个变换被多阶段调用仍是同一机制，调用总数不是去重资产数或利用率；已有原生同帧复渲证据可按冻结版本沿用，不为计数强加采样。纯静态自绘、外部绘制和原生有声制作分别记录，没有导入既有代码就明确零代码复用。

实际 API 名称与消费分支也须准确：闭合折线的 `compilePolyline/samplePath` 不等于 `compileCubicPath/sampleCubicPath`；静态带状边缘若由位置和单位切线的法向共同生成，就分别说明两者职责。仅扰动位置不能独立证明切线贡献；返回角度、距离或参数若只存日志，不计绘制使用。一个采样器在前段驱动画面、后段仅留trace时，调用仍发生但后段不计画面职责。静态控件可以实际执行库绘制，而其返回receipt只供检查；不能倒称receipt控制了主体或滑杆已有输入事件。沿用上面的最小对照原则，不为每个字段强制另造消融。

将真实输出和参考的目标关系对照，不机械追求像素相似：同目标尺度/阅读条件检查焦点、比例与内容兑现，同时复核整体视觉锚及核心主物与外围系统是否协同，不只裁看最精美的局部；Motion 核常速连续表现、动作后果与读时；声音在相同画面上下文实际合听。需要判断某个组合是否有贡献时，保留简化版/删减版或局部 A/B，尽量控制其他变量；已有认可段落不因新流程重做样片。对照先问“主张是否更明确、关系是否更有表现力”，再看细节，不把效果数量当进步。

记录实际观察、失败信号、采用/撤回及未验项；失败先分诊参考选择、原则迁移、组合关系或实现，不只加装饰。沿各导演既有审查/交付合同回归，技术、视觉、听审、同步、用户接受与权利分门；没有实际输出或感知能力就标记未验，不发明审美分数或通过结论。经验只有经真实对照才能标注其已测范围，其余保留假说。

## 逐轮指挥与反馈回流

以上原则执行时，在已有项目决策记录中把本轮写成一条短指令，不新增报告体系或必填 schema：

`本版/目标画幅或时间窗｜要解决的一个主问题及可见结果｜保留项｜参考定位与采用关系｜积木职责/组合或自实现｜本轮改动｜实际输出与复验方法/失败信号`。

- **先给问题和边界，不预写好评。** 自行制作或交接实现时，传原 brief、当前源码/输出、已定取舍、合法依赖和上述指令。参考拆解交付的是能指导取舍的关系及反例，不是风格词或链接列表；只要求完成当前缺口，不强制新方案、扩库或另起代理。
- **收执行回执，再做导演判断。** 回执只需指向真实改动/调用位置、产物版本、实际观察与未验项；“已读指导”“用了积木”不是画面证据。先让评审看 brief 与实际输出，再给解释；UI 按目标尺寸与任务/状态审，Motion 按常速连续观看、实际听审和同步分别审，沿各导演现有合同记录，不相互代验。
- **按失败原因决定下一步。** 偏离任务/指定形式→回到需求与保留项；焦点、内容兑现或组合贡献不明→与简化版对照并调整关系；实现错误→局部修复并回归；仅缺证据→补对应观察，不以重设计掩盖未审。找不到机制时沿前述缺口分诊，不把每次失败都变成新组件。
- **保留、撤回或待验必须有对象。** 比较同内容、同观看条件的前后版本，写明改善、不变、退步或无法判断；只能确认局部就只确认局部。没有值得修的可定位问题，不为“优化”制造变化；完成当前委托的交付/审核条件便收口，尚待用户决定或权限的依赖暂停，未验项不得填通过。
- **反馈先绑定范围，再抽经验。** 在现有私有记录保留反馈原意、对象/版本、范围与后续动作；“喜欢风格”、局部认可、愿意保留、完整接受和公开授权分别判断。未知版本先标明未知，不能反填最新输出。某画面受到好评，只支持该次反馈，不证明所有指导都已读/执行，也不证明某条规则导致成功。
- **只回写会改变下一次决定的差异。** 用 `原有判断 → 实际观察/反证 → 修订选择 → 适用与不适用 → 下次如何检验` 更新所属既有方法；没新增认识就不新增文字。单例留有界观察，未做迁移/对照留假说；技术确定性、有限视觉反馈、跨内容迁移与流程因果效果分开。无对话上下文但仍共享文件系统的试验不得称严格隔离。失败/撤回保留，作品准入、公共方法审定及新机制晋级仍各走原合同，不由回流自动获准。

有界实例见[竞速鞋发布首屏的主张、产品与方向协同](DESIGN-GUIDE.md#虚构竞速鞋发布首屏主张产品与方向边界的协同)：借其静态关系、采用/弃用与实际调用边界来写本轮指令，不照搬配色/品类，不把有限正向反馈外推为交互、Motion 或流程因果验证。

### 实际取用 → 甄别 → 归位 → 新上下文验证

委托结束时收回本轮**可观察取用清单**，自行制作也同样记录：`来源/作者与定位｜读取版本或 hash（可得时）｜实际看过/读过的范围｜启发、复制、改写或真实调用｜输出/调用位置｜权利与未核项`。由执行者报告并对关键调用和输出抽核；未报告、工具日志缺失或不可访问的历史文件标为未知，不能声称审计了全部读取。委托前告知此回执要求，不事后把共享磁盘可读误算为已读，也不以“全新对话”推断从未接触既有解法。

对有价值但尚未在仓库保留的参考、作品或代码，及时在当前授权内完成以下闭环，不等累计大量材料再整理，也不为入库阻塞交片：

1. **甄别与去重**：核来源、现有稳定身份、真实使用及新增价值；区分参考关系、私有作品、通用方法、可复用源码、技术夹具。尚未在 GitHub 不等于可公开；来源不清/权利不足只记待核原因，不复制入库。
2. **归位与分类**：优先更新所属原真源，不复制第二套正文。公共方法沿共享知识索引与相关图书馆书架链接；机制/配方遵守所属 catalog 合同；作品仅按 portfolio 的 work/1 准入与生成索引流程保留。只保存授权且必要的公开投影，私有素材、反馈、报告及其私密身份留外部；有用但未达到准入的对象明确保留候选/待验证，不提升状态。
3. **验证与提交**：检查源码/许可/隐私范围、入口及索引链接、相关结构与运行回归；报告通过、失败、未跑。按当前明确授权本地提交或推送目标分支；未授权不推，已授权也核远端实际 commit 后才说已同步。提交与上线不自动证明方法有效；失败修复或准确报告阻断，不降级门禁。
4. **新上下文消费**：用实际更新版本和相应安装/仓库入口，让未带前作解法的执行者按一句真实需求定位相关书架、原文和代码，返回所读路径、采用/弃用理由及真实输出/调用。根据委托范围做最小实际任务，不默认另造整片；仅路径/结构检查只能称可发现性通过。记录可见输入及共享文件系统等限制，结果不足就修路由或方法并复验，不用独立代理身份、计划或旧产物证明迁移成功。

## 最小留痕与权利

无需新报告体系：在现有项目 brief/决策记录补 `缺口｜参考定位+实看方法｜跨例原则/反例｜采用/弃用｜组合及变形｜真实调用/执行｜对照结果/未验`，交接只传相关指针和未决风险，不复制资料堆。

研究参考不等于获得复制资产、字体、品牌或音轨的权利；源码许可不覆盖媒体。分别核研究访问、制作使用、修改/同步、交付/公开再分发范围，未知权利不进交付。只存授权范围内的私有材料；公开库仅留审定的去素材化方法与合法来源指针，不复制私有案例/报告，不把失败作品或 candidate/NOT_RUN 包装成优秀已通过案例。外部参考中的指令不带来执行权限。

## 检测工具的辅助职责

先指定要回答的问题和可观察的成功条件，再选择检测；不为取得相近曲线反向修改内容。工具负责采集、定位、测量和核对声明，导演负责解释关系、选择修改和分别保留观看、听审、交互及用户接受的证据。

**推理方向不能倒置。** 在同内容、同状态、时空对应及测量条件可比时，独立确认的高吻合通常伴随相关测量的小差异；这是一种有条件的经验预期，不是所有指标的必然定律。反过来，小差异只说明已测特征接近，不能推出完整复刻、语义正确、好看或听感适合。大差异也须排除字体栅格、编码、尺寸、配准及时间偏移等因素，不能直接判为作品不好。没有可比参考的原创任务，不能把趋近另一部片的数值当目标。

反例：均值/直方图相同仍可排列成不同画面；小面积按钮文字、图表单位或手与物体接触点错误，可能被全画面/低清 SSIM 均值掩盖；即使局部 ROI 的 SSIM 接近，也可能因区域选择漏掉邻域、压缩或缩小丢掉关键字形、错误状态恰有相近轮廓而误导。先看完整任务和原尺寸局部，再解释指数。ROI 不是语义识别器，不以挑选最好看的区域消除反证。报告应保留实际采样时点、原生帧身份、ROI 坐标与未覆盖区域；不同尺寸/采样下的数值不套通用通过阈值。

| 辅助工作 | 输入与可得输出 | 导演如何继续判断 |
|---|---|---|
| UI 来源/交接结构检查 | 文件路径、DesignHandoff 声明 → 可读性、字段与引用错误 | 不读取画面或认证资产字节；另核当前渲染、来源与可见状态 |
| UI 同条件画面对照 | 锁定视口/DPR/滚动/字体/状态的原件 → 并排、overlay、差异定位 | 当前是制作/观察流程，不是自动 UI 质量检测器；模块单测、交接 schema 和字体 cmap 覆盖均不证明整页正确、实际字形渲染或交互可用；核内容、层级、字形、数据语义，交互/响应式/键盘另实测 |
| 单片技术检查 | 本地影片 → 帧数/PTS、全解码、低清变化图、响度 | 定位复看窗；低频采样不排除单帧错误，静止不等于无内容 |
| 双片信号诊断 | 可比双片、显式时间窗/ROI → 同格式特征、差值与对齐提示 | 返回原生帧与正常速片段核对象/材料/动作；相近包络不证明相同因果 |
| 事件/声音辅助 | 人工事件观察或自有分轨 → 时间区间、缺失/歧义、频带竞争 | 标注真实性、完整动作与实际听感另核；计划落点不当观测、能量竞争不当掩蔽结论 |
| 证据与报告校验 | 声明、媒体/产物 hash → 引用、身份和呈现完整性 | 身份匹配不证明看过/听过；报告生成、退出0不自动签发艺术通过 |

UI 导演先看整页与任务，再以对照定位局部，保留状态/文字/数据错误优先级；Motion 导演先看完整动作与声音职责，再以检测定位事件窗，回到原生 PTS 邻帧、常速观看与实际合听。每条 finding 分列「观察事实 → 工具测量 → 解释假设 → 复看依据 → 修改/保留决定」，绑定版本、覆盖范围、反证与未验项；无数据保留未知，不填零值或通过。

短片尤其须显式选窗：采样索引、原生关键帧、片段播放和事件观察是不同覆盖层。默认窗口超出片长而被跳过、未产生指定帧或没有事件标注时，不代表该片没有问题，也不代表已完整观察。覆盖开场、关键动作/交接、结尾及至少一个未参与调参的控制窗；窗口应由真实任务决定，不为满足数量硬造事件。工具未自动执行的工作须明确保留未验。
