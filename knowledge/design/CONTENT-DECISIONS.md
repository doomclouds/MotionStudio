# 内容如何选择 UI 表达

这是 UI 与 Motion 导演共享的**人工决策指南**，不是内容关键词→模板的自动匹配。已有方法卡仅是静态方法摘要（S：静态经验）；视频选择的专项建议为 H：待验证迁移假设，不是 V：本片视频实测。目录命中和代码测试不能把 S/H 升为 V。

## 每项设计先写六项，不先挑好看的皮肤

1. **内容事实**：要讲的主张、证据/数据、必须保持的对象关系是什么？是实际产品演示还是原创解释？没有真实数值，就不能造一个 dashboard 装作证据。
2. **受众与目的**：谁看、已有知识、观看屏幕、希望理解/比较/操作/感受什么？手机短片与桌面培训不能共享未经验证的信息密度。
3. **信息任务**：观众要比较数量、理解因果、追踪状态、记住步骤、辨认空间关系，还是体验情绪？一镜优先解决一个主任务；次任务须有明确读时。
4. **结构/风格/密度**：先选关系结构（并排、序列、网络、模块、单焦点），再定层级/色彩角色/字体/密度；“科技/高级/活泼”不足以决定结构。忠实复刻受源状态约束；原创重排需在 brief 中明确。
5. **媒介分支**：直接 UI 任务先明确静态、页面/状态、交互与响应式的设计及实际执行范围，不要求制作视频。Motion 委托再作**运动绑定**：每个动作回答一个信息问题，锁对象身份、前后状态、层序和阅读 hold；颜色、字号、光效不是运动机制。映射到 [MotionStudio 导航](../../skills/motion-film-director/references/design-to-motion.md)后查实际 API 限制。
6. **验证与退出条件**：固定目标设备/画幅/时长，先看静态层级；交互任务另验行为/视口，Motion 任务再常速观看。写出“观众应能复述什么”和误读风险；不能读清就减量/拆镜，不默认缩字或加速。听审与艺术接受另列。

## 按媒介选择专项

Motion 委托另读[内容到 Motion 的专项迁移假设](../../skills/motion-film-director/references/content-to-motion.md)，其表格与动作建议由 Motion 导演维护。直接 UI 委托依据当前页面/状态/交互任务作设计，不默认应用视频镜头、读时或声音要求。

## 冲突与未知时如何决定

- 受众、主张、数据来源、屏幕/画幅或授权任一关键项未知：列出缺项，先核必要事实；可画低成本结构草案，但不能称推荐已验证或擅自编数据。
- 忠实复刻与手机可读性冲突：明确报告冲突。保留原画幅分镜/局部查看，或另立原创适配 brief；不能暗中重排后仍称精确复刻。
- 信息过多与时长冲突：优先压减次要内容、分镜、延长读时；这些会改变委托范围时先取得决定，不靠极小字号完成形式交付。
- 多个方案都合理：列出各自要解决的任务和代价，用同内容/同画幅/同预算小样比较；不把主观偏好包装成统计优胜或模型能力提升。
- 目录无匹配/反例命中：允许“不推荐现有卡”。回到内容关系设计，记录 H；不为了复用强行改影片内容。

## 项目决策记录（留私有工作区）

`内容主张 → 受众/目的 → 主信息任务 → 候选与淘汰理由 → UI结构/色彩角色/密度 → 动作与读时 → 实际catalog ID及限制 → 证据等级S/H/V → 待测项/失败条件 → 本版复核结果`

已有静态方法提供的是设计观察与检查方法，不证明某种 UI 在任何视频里有效。只有当前明确版本实际制作、常速观看并核对理解目标后，才可为相应范围记 V；技术、听审、用户艺术接受和发布许可仍不得合并。
