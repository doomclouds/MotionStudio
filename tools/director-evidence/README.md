# 三导演的任务闭环与本地证据

这是仓库侧可选辅助工具，不是检索器、导演调度器或评审模型。读取图书馆和模型分析不以使用本工具为前提。实际记录留在已授权仓库外项目；公开库仅保留通用工具和合成测试。Motion portable 不包含此目录。

## 一次任务，一份设计说明

沿用项目已有设计说明、交接或 Case，不新建平行资产登记或逐资产打卡表。主负责人按本次需求推进以下闭环；简单任务可兼任职责，不强制三个代理全部启动。

1. **需求先行。** 明确用户要理解/比较/执行什么、真实内容、约束及最大误读风险。分清自主首版与反馈后修订。读[图书馆总索引](../../knowledge/design/library/INDEX.md)→相关书架→最相关自描述指南/契约、例子和反例。没有任务理由，不扫全库；不用语义检索替代阅读。
2. **选择必须落地。** 在已有说明中用短段落写所读具体文件/范围、采用或放弃的关系及理由、落在画面/时间/声音的哪一处。读后仍不理解则记录问题，不能把“工具输出了正文”写成“已理解”。借鉴原作只按授权观察，不读原作源码；自己的积木实现按需读。
3. **三导演解决不同问题。** UI 给内容层级、对象身份和状态；Motion 给因果、焦点交接及读窗；声音给事件职责、静默和掩蔽风险。主负责人合并成一个可证伪方案，记录有意义的冲突与取舍，不收集三份相同报告。没有声音需要可说明范围；未听过就保留 NOT_LISTENED，不将技术草案作为听觉结论。
4. **验证真实消费。** 采用项指向实际调用位置及本次执行证据。函数执行只是最低证据：还要观察返回值如何影响输出，必要时以同内容简化版/移除项反证。借鉴构图不是代码复用，import 不是函数调用，调用次数不是有效利用率。各自保留技术、视觉、实际听审、声画和用户接受的独立状态。
5. **有缺口才补。** 先区分导航未到、正文不自描述、合同不适合、组合方式不对、缺能力或审查条件不足。只补影响当前任务的缺口；不为了库存数量添加重复积木。交付不被扩库阻塞。
6. **收口时主动沉淀。** 当前执行者根据真实结果提出最小回写：修原自描述正文或现有 Case，明确适用、反例、调用入口、版本与未验边界；有新增资产才补其既有分类索引。失败也保留。提案与已写入、已审定、已收录分开，遵守权利与发布授权；不得由脚本自动宣称模型学会、作品通过或方法晋级。下轮从索引直达正文，复验变化影响。

自描述缺口优先补对象原有入口，不复制新卡库。应能回答：解决什么、不适合什么、输入输出、怎样调用、可运行例子、验证到哪里、来源与许可；场景还应解释组件关系和可变内容。声素材的积累必须同时考虑授权、事件职责、可听比较及实际听审，不能只堆文件或声学指标。

## 三职责怎样形成同一个可验证方案

在已有设计说明中围绕关键状态/事件交接，不新增三份报告：UI说明该事件代表什么、不代表什么及必须看清的内容；Motion确定其真实发生条件、视觉变化与留读窗口；声音提出提示、静默、尾音和掩蔽的职责。实现尽可能消费同一状态/时间来源；这支持计划一致，不能代替最终编码后的实际合看合听。样本采集完成不等于质量通过，模拟进度不等于真实设备测量；视觉措辞和声音语气都不能擅自扩大这个结论。

选择以任务语义为准，不以可用资产数量为配额：目标比不自动适合量程仪表，业务阶段推进不自动适合选卡接管镜头。相关反例允许当前负责人拒用成熟资产，采用简单机制或自主绘制；拒用需要具体不适配关系，不是为了报告看似全面而读完所有类别。三职责由一人兼任只证明该次责任有人承担，不证明三个独立代理已协作或能力充分验证。

### 声音先做有边界的候选，再由真实听审裁决

- 从事件职责选择声素材，说明开始/完成/错误等语义、出现频率、尾音占用与有意静默。素材合同或名称只能支持选择假说；候选已经生成、获合法授权或经 Audio Core 混入最终音轨，不等于声音被听懂或听感合适。没有适配项就明确缺口，不为用库而加声。
- 需要比较时保持同版画面、事件点和其他混音条件，明确唯一变化及可能混杂。先在同一播放器和播放音量听完整候选，记录能否区分事件、听清且不抢信息。若响度不同，保留原候选并说明差异；需要排除响度影响时另做受控比较，不偷偷调平后宣称原版获胜。同画面逐帧一致只证明视觉控制，不证明主观响度一致。
- 源文件峰值、混音电平、AAC存在或非静音只支持技术事实。电平低可能过轻，不能推导“非侵入且可辨”；数值安全也不能代替最终编码版本在实际播放条件下的听审。没有实际音频感知能力时停止听感优选和无依据微调，保留可播放候选、具体待听问题与 NOT_LISTENED；可继续不依赖听觉判断的授权技术工作。
- 原生渲染/混音报告绑定最终媒体；主线程探针只解释探针实际调用及局部反证，不能把探针计数当全片覆盖。消融环输入证明该输入影响相应像素，不证明所有返回字段被消费；返回坐标被源码引用与单独扰动后的输出反证仍是不同证据。报告中的 `passed` 必须注明技术范围，不能汇总成视觉、声音和作品接受全部通过。

### 动效验收必须回答时间带来了什么

先按当前委托区分静态图、可用的状态反馈和有表现力的动态短片。界面进度能用、函数执行、像素改变或声音准时，并不能满足动态表达的全部目标；没有完成常速观看时，不以静帧自审代签运动质量。

制作前由 Motion 提出最重要的时间关系及反证：观众会看到哪个对象由何状态转为何状态，什么可见原因带来什么后果，焦点何时交接，结果何时留给阅读。UI核对象身份、信息意义和读窗；声音对已经明确的事件做支持，不用提示音替代缺失的视觉因果。只为检查调用是否发生而定的合成brief，不足以检验表达性动效能力。

对当前同版输出常速完整观看，至少回答三个具体问题，不强制新增表单：

- 开始、发展和结果是否构成可感知且有意义的变化？主体/画面关系是否真的发展，还是同一块面板换字、数字递增、环逐渐填满？后者可能适合状态界面，但不能未经判断就称为达到动态短片目标。
- 连续播放比几个状态截图多表达了什么？选择最关键的变化窗，与同内容静态状态或简化版对照，观察过程、因果或焦点接续是否必要且读得清。静态对照不是要求所有信息都只能动画表达，更不以复杂性奖励动画。
- 用户要求的力度与节奏是否实际成立，是否有需要保护的安静读窗？定位具体时窗、对象与关系后再修；技术测量可定位变化或越界，但位移大小、运动像素比例、镜头数、平均帧差均不作为好看或“够动”的阈值。

反例：固定构图中的少量文字平移，加上计数/进度填充，可证明局部机制有效，仍可能整体近似静态；声点与切换同步也不能补足视觉表达。相反，强行全局推拉、无因旋转、堆粒子或缩短留读只增加动量，可能破坏任务。修订应先改变有根据的状态关系、可见动作后果或焦点接续，再选择机制；不强制相机运动，也不让库现有能力反向缩小用户的动态目标。

用户未指明版本时保留“版本未明确”，不猜测对应候选或把反馈绑定到某次输出。用户反馈按确切版本与范围分别保留：否定整体动效不抹掉局部声音卡点的正向观察，认可卡点也不外推音色、混音或作品通过。报告区分用户实际听看反馈、执行者亲自观察与程序事实；执行者未听就仍标未听。修订须补同条件常速对照及受影响的听审，不从另一版本继承接受结论。

### 从这次工作留下什么，而不把候选库变成认可库

收口时主动分清三类回写：已复现的执行/契约事实可在既有技术入口补准确用法；从有限观察得到的表达经验写适用范围与反例，待实际任务复验；声音角色与听感假说、用户偏好和未解决问题留在获准的私有 Case，并标待听，不能晋级为已听审推荐。

已有正文足够且导航可达就无需新建积木或重复经验。确有通用缺口时，提出或在授权范围内实施最小原位修订，补原分类索引的直达入口并验证链接；这才让下一次有理由找到它。公开回写不得携带私人报告、媒体身份或反馈，也不能把一次合成试验包装成充分的三导演能力验证。下一步若缺的是参考跨例观察、常速观看或实际听审，应补对应观察，而不是继续堆回执、素材或流程文档。

## 最小操作

Python 3 标准库；执行回执需 Node（仓库要求 Node 24+）。先确认命令/输入已授权，本工具不是沙箱，不会新增联网、发布或读取原作的权限。所有路径显式指定，不自动发现或扫描私有素材。

```sh
# PRIVATE 是仓库外、当前任务获准使用的目录。
PRIVATE=/path/to/private-project
python3 tools/director-evidence/evidence.py --store "$PRIVATE/receipts" read knowledge/design/library/INDEX.md
python3 tools/director-evidence/evidence.py --store "$PRIVATE/receipts" read path/to/guide.md --start 1 --end 40
python3 tools/director-evidence/evidence.py --store "$PRIVATE/receipts" run-node \
  --watch engine/motion-elements/lib/foundations/layout/ordered-bands.mjs \
  --output "$PRIVATE/scene.svg" "$PRIVATE/scene.mjs"
python3 tools/director-evidence/evidence.py --store "$PRIVATE/receipts" check
python3 -m unittest discover -s tools/director-evidence -p 'test_*.py'
```

`run-node` 运行真实入口并透传退出码；通过 Node 自带 V8 coverage 捕获显式 watch 文件，保留原始回执、stdout/stderr、源码运行前后 hash 和指定输出 hash。不执行源码字符串匹配推断。入口参数写在 entry 后，工具选项须在 entry 前。当前仅覆盖启动的 Node 入口进程主线程。保存 `entry_pid`，按 Node coverage 文件名的 PID/thread ID 筛选，仅主线程（thread 0）进入汇总；继承环境的子进程与 worker 原始覆盖保留并标记排除，不能满足本轮 watch。未识别的文件名也排除。此来源标签不是对抗性认证。不对 Python、浏览器、native renderer、子进程、worker或未列 watch 文件声称覆盖；coverage 缺失或显式指定的源文件未出现在覆盖中，`check` 会报观测缺口；导入但未调用的函数仍须看其零计数，不能把文件出现当消费。重复运行用不同输出路径保留版本，否则旧回执会因输出变化而过期。

## 能证明与不能证明

- `text_emitted`：工具实际读取 UTF-8 文件并向 stdout 输出指定行，记录整文件与输出片段 hash。外层工具截断、模型是否看到/理解、选择质量都不可观测。命令应控制在可见上下文范围；出现截断就续读相关范围，不升级为全文读过。
- `node_execution`：该运行的退出码及 V8 观察到的函数范围/次数。空函数名的模块顶层执行不能算 API 调用；计数为零的函数没有执行。函数进入不证明返回值被消费、屏幕有变化或对应资产整体通过。文件运行前后变化、缺产物和错误退出单列。
- 输出的 `changed_from_before=false` 不证明本次生成：可能是确定性重写，也可能是旧文件未动，需另外核恢复/执行流程。hash 只证明字节身份，不证明正确性。
- `check` 只检查现有回执绑定是否仍有效，始终报告 `acceptance: NOT_ASSESSED` 和 `model_understanding: NOT_OBSERVABLE`。空记录不能通过，但通过不代表任务闭环完成。工具不校验设计说明文风、不逼迫假填三导演结论。
- 这些是本地未签名记录，不防有意篡改；进程可修改环境、输出与覆盖文件，工具不能认证对抗性程序或人的行为。记录的绝对路径、hash、命令、输出可能私密，禁止直接提交公开库。不将手写记录冒充工具回执；工具回执也不能代替真实内容观察和用户裁决。

## 当前缺口

这补上可选的“正文输出/Node 执行→版本身份”辅助链，并未自动证明“理解→选择→组合质量→听审→方法晋级”。后半段由本次实际创作、评审与有边界的回写来完成。没有观察证据就如实留空/待验，不从格式合法制造成绩。无需增加查询后端、全库评分或强制台账。

## 实际试运行暴露的收口风险

- **区分新对话与新问题。** 新执行者能从分类索引找到并调用资产，说明导航与契约可用；若指南已有同题材消费者，不能再声称证明了陌生领域迁移、独立发明或三导演创意能力。报告既有提示、任务假设和未做的参考研究，不靠隐藏提示美化结果。
- **输出数字也要验。** 几何边界精确相加为1，不保证独立四舍五入的百分比相加为100%。UI负责显示精度、舍入提示及绝对量/份额区分；Motion负责过渡值不冒充真实观测、端点与读窗；声音负责有声需要与职责，不为补齐流程强加音轨。正式交付前发现的数据表达缺口须修复并重新绑定输出，不能只写入经验后仍声称成片通过。
- **消费反证有范围。** 固定其他条件，只改变所用机制的输入，核受影响区域和不应变化区域，可以支持该机制确实影响输出；不能据像素差推导观众理解更好或好看。自报trace是辅助数据，需与执行和输出证据交叉核实。
- **各阶段分别绑定。** Node绘图回执只覆盖列出的源码和产物；后来另行编码的影片、音频或报告不因前一阶段通过而自动获得身份绑定。按现有交付合同绑定最终媒体和本版评审。三张静帧不是全片常速观看，无音轨技术草案不是用户正式无声交付授权，未听审始终明示。
- **完整性不是完成度。** `check`通过只表示列出的回执字节未过期，不能代填缺少的阅读、参考、视觉、听审、用户接受或沉淀决定。收口先看本任务最关键的缺口，而不是继续增加回执数量。

回执格式v2增加进程/线程范围。旧v1正文输出回执仍可核字节；旧v1执行回执缺进程归属，`check`明确要求重新运行，不将历史混合覆盖静默提升为主进程证据。
