# design.color-sections.v1 · 主张与证据分区

## 设计意图
通过面积、阅读次序与颜色角色建立“先理解主张、再看证据”的关系。参考《幕启》的承诺/结算证据、《慢火》的黑白分割与《摩登焙香》的主视觉/月历区。抽象的是信息关系，不是某个SaaS卡片样式。

## 可以用 / 不要用
适合两个明确职责的内容块，横向并置或纵向展开。不要为了填满空白强行放第二栏；密集多列工作台、移动响应式、任意网格均超出本模块范围。颜色可同明度也可对比，必须由内容决定。

## API
[index.mjs](index.mjs) 导出 `draw(ctx, props)`。`bounds`，明确颜色的`theme`，`data.orientation` horizontal/vertical，`ratio` .25–.75，`gap`0–80，两个`regions`都有稳定id、role和fill。返回绝对坐标的槽位，其他积木使用这些bounds组成画面。禁止重复槽ID及无可用空间；本模块不自动绘制文案或证明“品牌感”。

## 不变量与兼容
两区加间隔恰好填满bounds，内容由配方绑定，外层控制层序。标题区的对比不可把证据淹没。颜色主题不自动继承父容器，配方必须显式传给子模块。不会改全局变换、时钟或数据。

## 证据
[examples/cases.mjs](examples/cases.mjs)包含横向“主张/证据”和纵向“故事/下一步”。统一组合作品实际向返回槽位注入不同内容和模块，不是只画两块颜色。本目录专项技术检查槽位几何、输入拒绝、状态隔离与两例差异；审美只能由真实图与用户审查判断。

来源作品：`portfolio/works/muqi-study`、`slow-roast-study`、`shanghai-deco-study`。没有改动原作工程；复制原作截图不计入验证。


## 冻结与当前实现

当前目录共置仅改变活动实现的导入/说明路径，算法与两个输入案例保持。现有作品仍固定原sourceCommit、模块hash与依赖锁；静态准入按历史源码验证，不改接受状态。当前catalog是新制作入口，不是旧锁的替代品；删除旧运行入口后，历史场景直接在当前检出运行不受保证，需按单件隔离恢复原则另行提供真实历史依赖。无自动恢复或新视觉验收。完整输入、限度与验证入口见[README](README.md)。
