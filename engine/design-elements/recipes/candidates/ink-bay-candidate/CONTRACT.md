# Ink-bay restricted contract

## Method, not a page
Each authored headline occupies one band. Its **actual ink** is anchored to the chosen left or right edge. The opposite bay is derived from that ink edge and one explicit gap; authored note lines must fit there. Note geometry is never supplied as an independent conflicting percentage. This is neither a universal typesetter nor a claim of new ink-measurement technology. The narrow additional method is the shared derivation of primary ink and residual note space.

`createRows({rows})` issues a frozen model.1..8 rows, each exact `{key,headline,side,notes}`; unique key1..24 ASCII identifier starting a letter, headline2..40 printable trimmed ASCII, side left/right,1..4 notes1..60. Unknown/accessor/symbol/hidden fields, sparse or augmented arrays, inherited indices and coercion reject; plain/null-prototype own-data records only. Internally owned arrays use own defineProperty appends. Trusted intrinsics, no adversarial Proxy/cross-realm or mutated native module sandbox.

`layoutRows(model,options,measure)` is the pure planner, with a trusted measurement callback returning exactly `{left,right,ascent,descent,advance}` in the Canvas convention. Scalars finite ±10000, positive ink width/height/advance. Callback honesty and correct font shaping are not validated. This function allocates no Canvas. `createInkBayKit(api).plan` supplies real pinned-font Native measurements and privately owns its plans; caller-forged plans reject.

Options are exact `{width,padding,rowHeight,rowGap,headlineSize,noteSize,noteLeading,innerGap,bayMinWidth,ink,noteInk}`: width360..1600 integer; padding8..64; rowHeight48..240; rowGap0..64; headlineSize24..160; noteSize10..28; noteLeading noteSize..2×noteSize; innerGap8..96; bayMinWidth24..600; opaque #RRGGBB colors. Height derives as2padding+n×rowHeight+(n−1)rowGap, ≤1800 and≤2M pixels. No hidden default or adaptive font reduction.

Headline ink is vertically centered in the band with2px top/bottom guards. Its left/right ink edge, not advance, anchors at padding or width−padding. Bay is the opposite horizontal interval after innerGap. Bay width must meet the authored minimum. Notes are ink-left aligned, with authored baselines separated by noteLeading; adjacent actual note bounds require≥2px. The whole note block is vertically centered. Every note must fit inside the derived bay with2px vertical guard. A1e−9 arithmetic comparison tolerance avoids roundoff-only rejection; it is not a raster allowance. Structural legality does not guarantee fit. No wrapping, truncation, ellipsis, overlap hiding, font fallback or Unicode/BiDi layout.

`kit.tile(plan)` creates one fresh transparent result. `kit.drawFresh(ctx,plan,dx,dy)` resets state per text operation and is only a fresh-context diagnostic/renderer helper. `kit.place(ctx,tile,x,y)` performs one save/drawImage/restore, preserves current path/state but inherits caller transforms, clip, alpha, filter, shadows and composite. Issued backing Canvas is mutable. Correct already-registered fixed BayDisplay/BayText aliases and honest fresh Native factory are required; use the external adapter to hash-check resources. Font registry is global trusted process state. Different kits do not accept each other's plans/tiles.

Native rasterization may change with origin/padding/platform. Continuous TextMetrics and finite expanded tests do not establish all-input pixel enclosure, exact inter-ink pixel gap, universal AA error bounds, cross-browser output or accessibility acceptance. There is no timing, animation, network, image input or whole-screen renderer.

## External resources and files
Only UTF-8 source, notices and fixed resource metadata are eligible for later text projection. No font binary, outline, image, screenshot, generated artwork, private audit or brand appears in source output. Native package/masters/derived aliases/output live outside source. Source and derived font bytes must match fixed identities before first registration; no system fallback. Commands create only absent normalized absolute external paths, with existing real parents and no live/dangling link components; exact package whitelist members are all regular files before output. Unknown contents are ignored, never recursively discovered. Single-writer filesystem checks are not TOCTOU/process isolation. Public repository integration/history gates and user approval of new compositions are separate.
