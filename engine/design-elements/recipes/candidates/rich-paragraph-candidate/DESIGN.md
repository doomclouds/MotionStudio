# Writing and composition guidance

**Use one paragraph to carry one thought.** The atom earns its place when ordinary prose, a small emphasized phrase and an exact identifier need to share a baseline and wrap as one reading unit. It is not a way to squeeze a whole article into a card.

1. Start at 18–24px and 1.6–1.8 line height. Check the actual font, not character count. Monospace code is wider; `WWW` is not equivalent to `iii`.
2. Emphasis should mark a decision or contrast, not every noun. The supplied examples use weight 600 and warm orange / violet; there is no default-green accent. Color is configurable and is not semantic by itself.
3. Give identifiers short names. `preview --local` or `shelf-07` stays intact. If an identifier or a styled word does not fit, widen the slot, edit the copy, or make it a separate block. Never silently truncate, condense or scale it.
4. Keep code chips quiet: restrained fill/border, small horizontal inset, no shadow. Their measured height participates in line spacing; a too-tight line height correctly rejects.
5. Paragraphs are not navigation, hyperlinks, accessibility trees, or live data. Produce an accessible text equivalent when embedding a raster in an interface.
6. Leave visual room after the paragraph. The output tile can be taller than its content. Avoid single-word last lines by revising copy, not changing the core's deterministic wrapping rules.

## Two uses of the same component

- **Fieldnote:** one broad body and a narrow dark note. Plain/em/code mix communicates a fictional release-writing method. Warm-paper and dark-sidebar backgrounds are composed outside the atom.
- **Collection workshop:** two equal editorial cards on a violet frame. Fictional inventory tokens demonstrate that the same code treatment works outside programming prose. The header, cards and footer are outer composition, not new atoms.

Both examples are new copy/layout combinations, not the Engineering Article page and not a new reference-work count. They use the same two fonts, four paragraph calls total, and the same measured implementation. The original blog's full-page anchors, drop-cap, masthead, stats, author details, performance story, reference image and hero placeholder were deliberately not migrated.

## When not to use it

Use a real text/layout engine for multilingual prose, RTL, hyphenation, selection, editable rich text, inline links, bidirectional scripts, or pagination. A CJK string is rejected honestly here. Do not stretch this atom's admission into an arbitrary rich-document engine. Existing typography/metric/layout families remain unchanged; this is an isolated candidate awaiting independent review and actual-brief reuse.
