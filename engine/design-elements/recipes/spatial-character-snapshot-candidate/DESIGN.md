# Spatial-character snapshot — 设计指导

## 这条配方解决什么

二维地址本身就是意义：空格不挤掉位置，字符不自动折行；格中标记与光标有确定的覆盖顺序。把同一格网 handle 交给摘要，保证维度、游标与各类计数不会和画面脱节。适合规则教学、路径示意、符号地图和离散状态快照，不是控制台、音乐软件或语法高亮编辑器。

它不同于已有 `value-grid` 的量程/单位/空值数值矩阵，和 `code-spans` 的顺序文本片段；也不是索引色像素图。这里只保留“字符地址＋状态覆盖＋同源摘要”一条受限配方，不新增 ASCII 族，不按 grid/summary 两个入口计两项机制。没有注册或改动任何现有目录。

## 两种异内容组合

- **Read a route**：32×14 的原创假想路径。浅纸画幅上有深色格网、下方同源摘要，右侧解释地址、覆盖和数据关系。路径只是作者的符号，不表示导航、真实地点或可执行程序。
- **Discrete pattern atlas**：40×18 的原创斜向符号场。深色纵向画幅、独立下方摘要，不同密度与字符、标记、光标位置。重复字符并不触发循环或运算；示例不是第二个引擎。

两例调用同一 gridTile/summaryTile/place，标题和背景只是组合代码；不是从原窗口剪裁，也没有引入原参考、截图壳、品牌、设备名、字体 CSS、外部吉祥物或原研究 fixture。

## 阅读节奏与色彩

先让观众认出网格的行列结构，再给少量标记，最后给一个光标。游标金色优先级最高；实心青/浅灰标记表示单元状态，bright 只高亮字形或占位点。低对比点只是空域节奏，重要事实必须由可见字符/摘要或讲解承担。当前角色色是固定配方，不宣传任意主题；浅色底上请加自己的深色舞台，而非默认为透明字已经有可读性。

保持 `.` 与空格语义不同：点有圆形占位，空格完全不画字，但仍可被背景标记和光标覆盖。不要把标记数当作非空字符数，也不要把 GLYPHS 当像素墨迹面积；DOTS/SPACES/GLYPHS 的分类规则见合同。

实际字体为 IBM Plex Mono Medium 500；用 24px 固定字号，先测墨迹再画。小格可能明确拒绝某些字符，不能为了塞内容悄悄裁字或拉宽某一列。2× backing 是静态采样选择，不是免费高帧率证明。

## 后续 motion 边界

本候选只有静态快照。若以后进入影片，先明确讲解任务，使用既有 absolute-time、opacity/transform 或 layout-handoff；每个变化后的格网与摘要必须从同一帧新 snapshot 重建。镜头缩小可能让符号消失，应实看编码后帧并留阅读时间。跳帧/倒序、长循环内存、帧率与中间态尚未验证，不因导出图片成功就声称可实时运行。简单显隐不是新基础机制。
