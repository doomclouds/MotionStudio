# Pair a headline with its remaining space

Use this when each short statement has a directly related annotation: exhibition object/category, film credit/role, venue/route detail, or section/title commentary. The primary statement and note form one authored semantic pair; they should not be unrelated filler chosen to occupy a hole.

1. Choose headline content, size and edge deliberately. A large word is not automatically more important; vary edges only when it supports a clear reading rhythm.
2. Anchor the **ink**, including side bearing, rather than assuming advance is the visible edge. Ink-alignment itself is established typography and already exists in other components; it is not the novelty claimed here.
3. Derive the opposite note bay from that edge plus a declared gap. Changing headline content changes available note width. Do not keep a stale independently authored note rectangle.
4. Supply note line breaks and minimum bay width explicitly. If notes fail, revise content/size/geometry; never silently shrink, hide or wrap into the next row.
5. Keep annotation visibly secondary, but choose contrast and final output scale for reading. Fit is not accessibility or aesthetic approval.
6. Combine transparent row groups with independent margins, dividers or other content. The API is not a navigation bar, giant Ferrule clone or fixed three-row poster.

## Deduplication boundary
`typographic-focus` already supplies kicker/headline/body hierarchy; `expressive-type` already aligns actual ink for effects; `rich-paragraph` wraps styled runs and checks bounds; `feature-stack` sizes regular columns; `authored-dialogue` groups note rows; `sampled-window` and `complementary-seam` sample/partition source images. None of these facts is counted as new here. This candidate narrowly binds an authored same-row note bay to its paired headline's actual occupied interval and reports both from one plan. It adds0 registered families or formal recipes; it is a candidate extension only. If a task just wants fixed left-aligned text and a paragraph underneath, use the existing typography family.

## Do not use
Long paragraphs, arbitrary responsive web copy, logos, CJK/BiDi shaping, automatic tag packing, general polygon text flow, data encoding from decorative widths, inaccessible tiny annotations, or simulated animation. Space allocation is geometry, not statistical information. Static author tests cannot establish owner aesthetic acceptance.
