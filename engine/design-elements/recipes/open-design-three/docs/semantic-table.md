# 短文本记录表配方
原FlowAI表的5行7列、固定offset、固定绿色第5列与头像形状是案例布局，不是可迁移语义。此候选把列key/label/fraction/role、稳定row.id和每格text/emphasis显式化；只允许status列强调。颜色不暗示成功率或数值大小，数据保持文本原样。

`planTable(ctx,p)`先验证及测量；`drawTable(ctx,p,{createCanvas})`离屏后一次合成。2–7列、1–12行；width360–1600；每列至少55px；行高28–64；字体10–24px且小于行高-10；单行80字上限且按实测宽度拒绝。列fraction和为1；重复ID、未知格属性、缺格/多格、非status强调全部拒绝。不会自动截字/省略/伪造排序，行顺序按输入保留。

示例生产流程（3列3行带状态强调）与博物馆日程（3列2行无状态）使用同一实现，分别深蓝铜色、奶白紫色。它们是合成示例，不是真实运营数据。原FlowAI源码不调用新接口，需另做迁移回归才能说替换成功。

与semantic-data的圆面积编码、ratio-rings比例、recipe.value-grid的热色矩阵都不同；不将表行数字渲染为无依据面积。与parameter-controls也不同，状态文本不是可交互控件。仅候选配方，未来若真实跨项目调用稳定才考虑族抽象。
