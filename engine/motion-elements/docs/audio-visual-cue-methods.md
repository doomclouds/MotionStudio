# 本地合成声音：从真实调用到可复用候选

本页是**知识沉淀与尚未实现的设计提案**，不新增已登记基础、配方或 API。它补充声音职责与听审指南，不替代合法音效寻源，也不把本地合成设为所有作品的默认最佳选择。

阅读路径随分发形式不同：仓库中配套指南为 `skills/motion-film-director/references/sound.md`、`sfx-sourcing.md`、`engine-use.md`；独立 Skill 包中为 `references/` 下的同名文件。本页在仓库是 `engine/motion-elements/docs/audio-visual-cue-methods.md`，在独立包是 `runtime/motion-elements/docs/audio-visual-cue-methods.md`。

## 1. 证据分层：项目事实、通用知识、未来能力

一组已制作的三个有声短片，其实际声音脚本都在本地离线运行：NumPy 构造浮点采样，Python 标准库 `wave` 写 PCM；其中一片另外使用 SciPy 的滤波函数。节点/几何由视觉源码求值，Node 调用 FFmpeg 将最终 WAV 编码并封装进影片。不是调用音乐生成模型、外部采样音源库或 DAW；这组脚本没有通过 `motion-audio-core` 作曲。

| 已查项目形态（匿名） | 实际方法 | 数据绑定与限界 |
|---|---|---|
| 界面排期短片 | 振荡器叠加、带衰减的拨弦/低音、变频低鼓、种子噪声、显式起落包络、声像、少量非线性整形 | 拖动、释放和确认音采用两侧手写的绝对秒数；另从最终浮点混音计算逐帧 RMS，实际驱动画面的小音量表。卡片内装饰波形不是录音波形。 |
| 标量场轮廓短片 | 谐波短音、和声层、脉冲、移动平均平滑噪声、短延迟副本、合成材质提示 | 已测得的原生拓扑变化时点被人工写进音频脚本；音频脚本未自动读取事件回执，也无实时拓扑回调。不是看到画面后自动“找鼓点”。 |
| 柔性连接短片 | 正弦分量与衰减包络、Butterworth 带通噪声、扫频提示、左右交换的延迟副本 | 触碰、插入、沿线提示与亮起按作者指定时轴编排。片尾固定缓冲和总淡出可截短晚入声部，不等于每个声部都完整释放。 |

这些版本曾做源产物精确重建、最终编码音轨技术检查及声画时点源码核对。**用户对这一组三片的声音卡点给予笼统正向反馈**；它不是逐片、逐音色、每个参数或通用机制的认可，也不能改写审查者未实际听审的事实。组级用户反馈、独立技术核查、实际听审/正常速度观看必须分栏。私人原话、消息标识、作品媒体和实际配方不进入本页。

这里的 `voice` 指一个合成声部，不是人声配音或 TTS；这些源码没有语音合成/旁白。

通用 DSP 名词只是解释上述代码职责：正弦分量相加不代表真实乐器录音；滤波噪声不自动成为真实环境拟音；移动平均噪声窗不能仅因注释写了“granular”就称为颗粒合成器；少量延迟副本不等于房间脉冲响应卷积混响；RMS 不等于节拍检测或主观响度。

## 2. 可迁移的制作关系

### 先绑定语义，再决定是否卡在拍上

- 先列实际画面事件：开始准备、接触、真正提交、释放、状态改变。准备音可以有意先行，完成反馈不能无说明地提前宣告完成。
- 音乐脉冲与视觉事件是两条轴。规则脉冲可形成运动感，但不要求每个动作都落在鼓点上；不要把一个重复的时间间隔推断成整曲统一拍号/完整音乐结构。
- 字面同秒不保证听觉峰值同帧：声部可能有 attack，视觉只能在帧网格取样，AAC 又有编码器延迟/呈现语义。记录语义时点、声部开始、预期听觉重点、首个可见帧及实际封装检查，最后仍需正常速合听。
- 已测事件写进另一份脚本是**手工绑定**，不是统一事件系统。改画面时两边都要复核；生成过某个 JSON，不代表音频真正读取了它。

### 声音的层次不是“更多声音”

背景层负责连续性，稀疏脉冲负责推进，事件提示负责因果，结尾和声/尾音负责释放。音区、声像、织体密度、休止和角色分工要一起考虑；不能靠恒定蜂鸣、统一增益或更多 cue 代替发展。参数变体不是新机制。对已有组级好评，优先保留已验证职责关系，不机械复用旋律、频率、种子或全部时点。

### “确定性”必须带环境与调用顺序

固定种子仅是必要条件之一。当前项目使用的共享 RNG 会随抽样调用顺序推进；不能推导出任意重新排序声部也字节不变。需记录生成器、源码、数值库/运行时、采样率、处理顺序、声道、输出格式和源身份。同一固定环境中的 PCM 重建，与跨平台浮点相等、AAC 字节相等和听感相同分别验证。

### 尾音政策显式化

逐声部记录 `开始 / 名义支持区间 / 实际写入区间 / attack / release / 延迟尾 / 被裁掉多少`。一种项目实现会拒绝越界声部，另一种会把写入区间截到固定片长；两者不能共用“所有声部完整”标签。总混音淡出只能处理其覆盖的片尾，不能修复中途某声部的硬截。建议默认拒绝未声明越界；需要裁尾时明确创作选择、使用的边界处理及复听，不偷偷补静音或延长影片。

## 3. RMS → 画面：已发生的数据流与通用化边界

已核项目的小音量表使用的是**最终浮点混音、写 PCM 前**的 RMS，不是麦克风、单卡录音或最终 AAC 解码后的 RMS：

`合成声部 → 包络/声像 → 相加与作者处理 → 浮点 master → 按视频帧划窗 → RMS → 显式归一/限幅 → 特征 JSON → 场景按帧读取 → 实际绘制音量表`

在采样率恰能整除帧率的例子中，每帧可以使用固定样本数；不能把这点推广到所有帧率。拟通用化时：

1. 用准确的绝对有理时间定义帧窗 `[t_f,t_(f+1))`，再使用现有时间量化规则得到样本边界。非整数每帧样本数时窗长允许变化，不能反复累加四舍五入的固定长度。
2. 明确数据域是 pre-PCM、源 PCM、某个 stem 还是最终编码解码 PCM；保留该数据域身份。重新混音或编码后不得沿用另一数据域的 hash。
3. RMS 需写清是否跨声道求均方、窗长/步长、空窗策略。先混成单声道再平方会受相位抵消影响，和双声道各自平方后平均不同。
4. 归一方法是显示设计而非响度校正。分位数为零的全静音输入必须有明确规则；不能除零、生成 NaN 或悄悄放大底噪。限幅后的表格也不能再被当作原始能量。
5. 全片分位归一会使用未来样本，因此此方案是离线特征导出，不是已验证的实时麦克风表。实际峰值、RMS 或九格显示都不替代听感。

## 4. 先复用现有核心，避免重造和重复计数

- `motion-timeline-core` 已提供有理时间、帧/样本转换、范围与编辑操作、clip/stem/bus 路由合同和创作身份。`timeToSamples` 使用最近采样、平局远离零；共享绝对端点只量化一次，再相减得长度。参见[时间核心 README](../../motion-timeline-core/README.md)与该包 `lib/timeline.mjs`。
- `motion-audio-core` 已提供已授权本地源准备、裁切/混音、gain/fade、显式路由、PCM 输出、编码检查与测量。它不会默默加 limiter、归一化、EQ、压缩或 sidechain。参见配套 `engine-use.md` 的实际音频入口（路径见页首）。
- 这组 Python 项目没有因此成为上述核心的新功能。未来生成器可先产生明确授权、身份固定的本地 PCM，再通过现有核心编排；具体 adapter、参数 schema、尾音合同仍须设计和测试。

## 5. 潜在声音积木/配方——全部 NOT_IMPLEMENTED

下表是候选职责，不是 API 清单或已入库数量；术语和函数名尚未冻结。标准 DSP 算法、参数变化和每种音色不分别登记为基础。

| 候选职责 | 输入/输出与必需合同 | 应复用/不得承诺 |
|---|---|---|
| 有界确定性声部生成 | 显式振荡器分量或噪声类型、种子、时间、包络、声像 → PCM＋声部支持区间回执；限制时长、声部数、频率/滤波合法域、内存 | 不内置“高级/好听”标签；不能把 felt/bell 名称当真实乐器。是否用 Python 或核心语言实现尚未决定。 |
| 声部尾音与边界检查 | 名义声部/延迟支持区间＋项目范围 → 完整/显式裁尾/拒绝及被裁样本数 | 现有 clip fades 继续复用；不增加另一个隐藏混音器。尾样本为零也不代表无可听瞬态。 |
| 离线 PCM 特征导出 | 明确来源域的 PCM＋有理帧窗＋声道与归一策略 → 原始 RMS/显示值＋身份 | 不是 beat detector、实时输入或 LUFS normalize；需全静音、短片、非整数帧率和相位反例。 |
| 显式事件绑定编译 | 同一事件记录＋声音角色/偏移＋视觉消费声明 → 音频 cue、视觉时间输入、量化与覆盖日志 | 复用现有时钟与样本转换；不是通用自动卡点、自动作曲或动态事件监听。 |
| “准备→动作→完成→尾音”编排配方 | 显式角色与声音素材/声部引用、音乐留白、结果反馈和尾音空间 → 可审查计划 | 只是组合候选；不强制每步发声，不默认 ducking 已实现，也不把配方计作基础。 |

若后续引入“每 voice ID 的独立随机流”，需固定稳定 ID→种子的规则与 PRNG 版本，测试重排/增加无关声部的影响；**当前共享 RNG 项目没有这个保证**。不可因提案存在就改变已冻结作品的声源或宣称旧片调用了新接口。

## 6. 单一事件表提案：先消除两份手抄时间

**以下是独立合成示意，不是现有解析器可执行的 schema。** 不应交给当前 `validateTimeline`；它的未知字段仍应拒绝。

```json
{
  "proposalOnly": true,
  "events": [
    {
      "id": "panel-settled",
      "at": {"n": "17", "d": "10"},
      "origin": "authored",
      "visualRole": "settled",
      "audioRole": "soft-confirmation",
      "cueOffset": {"n": "0", "d": "1"},
      "intentionalSilence": false
    }
  ]
}
```

拟议流程：

1. **作者事件**由唯一数据源提供有理时间；**测得事件**先从不依赖音频的原生状态预检得到，绑定视觉源码/参数/采样版本，再冻结事件表。视觉修改导致回执失效，不自动沿用旧时点。
2. 声音与画面都消费同一事件 ID，而不是各抄一个浮点字面量。事件记录还要规定 onset/峰值/释放的职责和是否有意静默；`cueOffset` 必须可解释，不能隐式提前完成反馈。
3. 音频用现有绝对时间→样本规则；视觉另明示“首个不早于事件的帧”等采样政策。上例在 48 kHz 下为样本 81600；若画面为 24 fps，首个不早于该事件的帧是 41，即约 1.70833 秒。两者属于同一时轴，却不是同一个离散瞬间。编译回执应记录偏差，不伪造零误差。
4. 输出应含 `eventId / 语义时点 / cue开始与预期重点 / 源参数身份 / 样本索引 / 首个视觉消费帧 / 偏移理由 / 尾音支持区间 / 消费者列表`。单一数据源只防漂移，仍要以真实绘制和实际 PCM 证据核消费。
5. 非法/重复 ID、未知键、非有限值、未解析角色、循环依赖、越界 cue、量化为空或顺序冲突必须有显式失败合同；无事件不等于自动补 cue。生成器、视觉采样、封装与审查分别有身份。

这套统一事件编译、自动过期检查和消费者覆盖日志**尚未实现**。已有手工事件表、Python 列表或原生 usage 回执不能冒充它的落地证据。

## 7. 实现前后需要的验证

先固定最小资源域和尾音政策，再做合成输入测试：音高/滤波边界、全静音、声道、首尾与相邻样本、事件重复、非整数帧率、共享端点、随机流/调用顺序、反向/重复 seek、全新进程和源变动拒绝。另查谐波/非线性整形带来的混叠风险；没有带限或过采样合同，不得承诺任意音高/整形参数下无混叠。测试文件只用独立合成参数，输出写临时目录，不提交 WAV/MP4、字体、私有生产参数或密钥。

在真实新作品中逐层记录：新接口真实调用 → 返回 PCM/事件被消费 → 可重建 → 最终编码完整解码/响度与真峰技术观察 → 同画面正常速听审 → 用户范围明确的反馈。不得用技术测试、组级正向或参数规模替代最后两层。未实际听时继续写 `NOT_LISTENED`；尚未编码、迁移或用户未评分别记未验，不用统一 PASS 覆盖。

## 8. 持续维护：每次作品携带证据与限制

本页是可持续修订的知识记录，不是一次正向反馈后冻结的“通用音效公式”。后续作品采用、修改或否定相关方法时，先在私有记录保留该版本，再决定是否形成公开的可迁移增量：

- **私有案例最小记录**：作品版本与源/媒体身份、实际调用和生成链、使用的工具/许可、事件语义与声音时点、真正消费的特征数据域、原始测量与重建范围、实际听审/常速检查、用户反馈的对象和范围、反例/未验项。没有发生的检查不得补成 PASS。
- **公开更新最小记录**：日期、一般化问题、可迁移规则发生了什么变化、适用条件与反例、证据类型/覆盖以及仍然缺什么。保留匿名化的反馈范围，不带原话、消息 ID、项目路径、原始媒体、私有配方或秘密。
- **修订而非覆写历史**：发现术语、事件映射或尾音合同错误时，纠正当前文字并保留私有旧回执/变更原因；新片使用了新版生成器，不反向声称旧片已调用它。公开链接和工具定义改变时核查所指版本。
- **候选升级门**：只有真正实现、边界/资源测试、独立复核及真实新作品调用证据成立，才讨论将表中某职责变为稳定接口或登记项；文档新增、调参数或用户组级反馈不自动增加计数。听审和艺术门仍独立。
- **不要为更新而推翻认可**：有明确正向反馈时保留其版本和范围；后续仅针对新需求、可定位缺陷或获得的新证据迭代，优先局部对照。不同用户/设备/内容的反例也应保留。

持续维护不等于后台自动访问私人素材或调用付费分析。每次生产/研究仍遵守当前权限、来源许可与外发边界；公开发布使用单独源文件白名单，不把案例档案随指南打包。

## 9. 来源与权利边界

- 经验来源是私有作品的实际源码、产物重建、原生调用及编码检查；精确媒体/源身份和反馈原文由私有审计记录保留。公开页不附作品音频、生成配方、项目路径或消息 ID。
- [NumPy 2.3 Generator](https://numpy.org/doc/2.3/reference/random/generator.html) 与 [convolve](https://numpy.org/doc/2.3/reference/generated/numpy.convolve.html)：核对生成器、随机流与卷积的具体职责；固定 seed 不应被提升为任意跨版本字节保证。
- [SciPy 1.17 butter](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.signal.butter.html)：带通的最终阶数为 `2*N`；`butter(2, ..., btype='bandpass', output='sos')` 是两个二阶节、总四阶，不应简称为总二阶滤波器。`sosfilt` 执行这些级联节，不生成乐曲。
- [Python 3.12 wave](https://docs.python.org/3.12/library/wave.html)：项目使用标准库写无压缩 PCM WAV。FFmpeg 的本地 `-h filter=ebur128` 描述测量职责；测量器显示的 target 不等于源码已执行响度归一化。
